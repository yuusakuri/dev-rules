# 通信プロトコル実装ガイドライン

## 1 はじめに

### 1.1 目的

本書の目的は、通信プロトコルの設計者及び実装者が、通信路の制約に合わせて送受信の仕様を定義し、異常な入力からの復帰を検証可能にすることである。

### 1.2 適用範囲

本書は、新しい通信プロトコルの設計、実装及び検証について規定する。

既存の通信規格及びシリアル通信実装は、各層の役割及び処理方法を考えるための設計例として参照する。

## 2 通信層の分担

通信の各層に、入出力の単位及び保証する動作を割り当てる。下位層の機能を確認した上で、フレーム境界、順序、誤り検出、再送及びアドレスの担当を決定し、処理の重複又は欠落を防ぐ。

上位のメッセージを複数のフレームに分割する場合は、識別子、順序、再構成の上限及び欠落時の処理も定める。

実装では、フレームの読み書きと、通信開始・終了などの状態管理を分ける。

PPPでは、フレーム化を担う仕様と、リンク又は上位プロトコルの設定を担う仕様が分かれている。

## 3 フレーム境界と符号化

### 3.1 一般

下位層がメッセージ境界を保つ場合は、その受信単位と設計するフレームを対応付ける。

バイトストリームを扱う場合は、長さ又は区切り文字からフレームの境界を求め、データが壊れたときに次の境界を探す方法も決める。

### 3.2 長さに基づく区切り

長さフィールドを持つ方式では、ヘッダーから後続データの長さを読み取り、フレームの終端を求める。

長さ自体が壊れた場合に備え、同期用の値又は検査値と組み合わせて次のフレームを見つける手順を定める。

### 3.3 予約値とデータの区別

区切り文字を使用する方式では、同じ値がデータに含まれるときのエスケープ表現と、不正な列又は空フレームの扱いを定める。

SLIPはENDでフレームを終え、データ中のENDとESCを別のバイト列に置き換える。

処理単位は通信路によって異なり、PPPのHDLC-like framingでは、非同期回線で予約バイトをエスケープし、ビット同期回線では連続する5個の`1`の後へ`0`を挿入する。

### 3.4 COBSによる符号化

COBS（Consistent Overhead Byte Stuffing）は、ゼロの位置をコードバイトで表して`0x00`を含まないバイト列にし、末尾の`0x00`でフレームを区切れるようにする。

符号化後のサイズは、入力長を`n`バイトとすると`n + floor(n / 254) + 1`バイト以下なので、終端用の1バイトを加えてバッファを確保する（`floor`は小数点以下の切り捨てである）。

空データと末尾のコードの表現を決め、復号時はコードが示す長さを入力の残り長さと照合する。

送信しながら符号化する場合は、コード確定までの最大254バイトの先読みを考慮し、必要なバッファと送信開始までの待ち時間を見積もる。

## 4 フレーム内容と検査

### 4.1 フィールドの定義

各フィールドの順序、幅、値の範囲及びバイトオーダーを定め、採用するフィールドについて[表3](#table-3)の内容を仕様へ記載する。

<a id="table-3"></a>表3−フィールドの定義

| フィールド | 定義する内容 |
| --- | --- |
| バージョン | 形式の互換性と、未知の値を受け取ったときの処理。 |
| 種別 | ペイロードの解釈、予約値及び未知の値を受け取ったときの処理。 |
| 長さ | 数える範囲、単位、最小値・最大値及びヘッダー又は検査値を含むかどうか。 |
| 識別・順序 | アドレス、チャネル、シーケンス番号などの役割と、重複・欠落・順序逆転の扱い。 |
| ペイロード | データの形式、最大長及び空データの扱い。 |

格納可能なデータ量は、通信路の上限と、各層のヘッダー・検査値・符号化による増加量から求める。

識別子へ送信優先度も割り当てる場合は、CANのように値が競合時の待ち時間へ影響するため、その関係を仕様に含める。

送信するバイト列は、定めたフィールドの幅とバイトオーダーに従って組み立てる。

### 4.2 データの検査と保護

検査値の計算対象と符号化との順序を定め、送受信で同じ範囲を検査する。

受信側は、形式と検査値を確認してからペイロードを上位層へ渡す。

PPPの非同期フレームは、FCSを計算してからエスケープし、受信側でエスケープを復元してから検査する例である。

COBSを使用する場合も、伝送誤りを検出する検査値を別途設ける。

CRCを使用する場合は、生成多項式、初期値、入力・出力のビット順反転の有無、最終XOR、検査値の幅と格納順序を定める。

改ざん又はなりすましへの対策が必要な場合はMAC又は署名を、機密性の保護が必要な場合は暗号化を設計する。

## 5 受信処理とバッファ管理

### 5.1 一括入力と解析状態

解析器は、受け取るバイト列の分割位置によらず、同じ解析結果を返すAPIにする。一括入力に対応し、解析途中の状態を次の呼び出しへ保持する。これによって、1バイトずつの入力及び複数のフレームの一括入力を同じ仕様で処理することが可能になる。

解析状態は、入力に応じた遷移、保持するデータ及び完了・失敗の判定を状態機械で表す。

内部で1バイトずつ解析する場合も、読み取り、ロック取得、タスク起動及びメモリ確保は入力又はバッファの単位でまとめる。

ZephyrのModbus RTU実装はUART FIFOから空き容量に応じてまとめて読み取り、Linuxの非同期PPP実装は通常のデータが続く範囲をまとめてフレームバッファへコピーする。

### 5.2 バッファの上限と所有権

受信した長さは、整数演算が範囲内に収まることと最大フレーム長を検証してから、バッファの確保又は参照に使用する。

受信バッファ、未処理入力及びキュー件数には上限を設け、超過時の破棄又は再同期の処理を定める。

ペイロードを参照で返すAPIでは、参照が有効な期間とバッファの再利用時点を明確にする。

その期間を超えてデータを保持する必要がある場合は、所有権を移すか、必要な範囲を所有バッファへコピーする。

## 6 通信状態と障害からの復帰

### 6.1 受信エラーとタイムアウト

検査値の不一致、形式不正、長さ超過及び入力の途中終了などを区別し、発生数と解析状態を記録する。

フレーム受信、応答、送信及び再接続には待ち時間の上限を設け、期限切れになった処理を終了できるようにする。

不正なフレーム又は期限切れのフレームは破棄し、次の境界を検出できる状態へ戻す。

### 6.2 再送と接続状態

再送する場合は、要求と応答を対応付ける識別子、再送回数・間隔、期限後の応答の扱い及び失敗とする条件を定める。

要求の重複に備え、同じ要求を繰り返しても一度の処理と同じ効果になるようにするか、識別子で重複を判定して処理を一度に限定する。

接続を確立する方式では、接続前、設定中、通信中及び終了時に受け付けるメッセージと、イベント又は期限による状態遷移を定義する。

PPPはリンクの確立・設定・終了を状態遷移で表し、PPPoEは相手の発見とセッション中の通信を分けている。

再接続時は、解析途中のデータ、シーケンス番号、応答待ち、再送キュー及び認証状態を引き継ぐか破棄するかを決める。

## 7 検証

### 7.1 送受信と異常系

[テストガイドライン](../software/testing-guidelines.md)に従い、仕様から期待するバイト列と解析結果を用意して、送信・受信を個別に検証する。

往復変換と独立した送受信実装の接続も確認し、[表4](#table-4)の入力又は状態で仕様どおりに動くことを確認する。

<a id="table-4"></a>表4−検証対象ごとの入力及び状態

| 検証対象 | 確認する入力又は状態 |
| --- | --- |
| 入力の分割 | 完全なフレーム、任意位置での分割、1バイトずつの入力及び複数フレームの一括入力。 |
| フレーム境界 | 空フレーム、連続する区切り、終端不足及び通信ノイズ後の入力。 |
| フィールド | 最小長・最大長とその前後、未知のバージョン・種別、予約値、バイトオーダー及び長さ不一致。 |
| COBS | 空データ、254バイト境界の前後、ゼロの連続、ゼロを含まない最大長、不正なコード、終端不足及び連続するフレーム。 |
| エスケープ | 予約バイトの有無、予約バイトだけの入力、連続・不正なエスケープ列及び最大増加量。 |
| 誤り検出 | ヘッダー・ペイロード・検査値のビット反転、検査範囲の境界及び誤った初期値・バイトオーダー。 |
| 復帰 | 長さ超過、キュー満杯、タイムアウト、切断・再接続、重複要求、応答の欠落・遅延及び順序逆転。 |

### 7.2 転送量と処理時間

性能の測定では、通信速度、CPU、入力サイズ・内容及び同時実行数を記録し、比較する項目以外の条件をそろえる。

転送量は、最悪時の符号化による増加と区切りを含めて求める。

予約バイトを2バイトに置き換える方式では、対象データが全て予約バイトになる場合の2倍の長さに、区切りなどの固定部分を加える。

付加ビットを含むデータ量を通信速度で割り、フレーム間隔を加えた最大転送時間が、許容する待ち時間に収まることを確認する。

処理負荷は、送受信の呼び出し回数、CPU時間、最大バッファ長、メモリ確保回数及びコピー量で評価し、破損した入力から再同期するまでの時間も測る。

入力をまとめるサイズも変え、呼び出し負荷と、データがそろうまでの待ち時間の関係を確認する。
