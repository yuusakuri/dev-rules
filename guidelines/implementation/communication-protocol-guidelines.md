## 1. 概要

本書は、ネットワーク通信、シリアル通信、CANなどを使って独自の通信プロトコルまたはバイナリ形式を実装するときの設計と検証のガイドラインを定める。

本書は、[ソフトウェア設計ガイドライン](../software/software-design-guidelines.md)を前提とする。

通信相手が既存の標準プロトコルを要求する場合は、独自形式を作らず、対象プロトコルの仕様と利用可能な実装を確認する。

既存プロトコルをアプリケーションへ接続するアダプターを実装する場合も、受信単位、エラー、上限及びタイムアウトの扱いを対象プロトコルに合わせる。

## 2. 通信層の境界

### 通信層を分けて設計する

物理層、データリンク層、トランスポート層、メッセージ層及びアプリケーション層を区別し、それぞれが提供する境界、順序性、誤り検出、再送及びアドレスの責務を明記する。

下位層が提供する機能を上位層で重複して実装すると、転送量、遅延、状態管理及び障害時の挙動が複雑になる。

受信データがバイトストリームとして渡される場合は、読み取り結果の境界をメッセージ境界とみなさない。

UART、TCP及び同様のストリームでは、1回の読み取りに含まれるバイト数が分割位置やフレーム境界を決めない。

受信データがCANフレーム、UDPデータグラムなどのメッセージ単位で渡される場合は、既存のメッセージ境界を利用し、同じ境界を作るための区切り文字や長さフィールドを追加しない。

上位のメッセージを複数のCANフレームへ分割する場合は、CANのフレーム形式と上位の分割・再構成方式を別の層として定義する。

### 既存プロトコルを再実装しない

相互接続する相手がHDLC、PPP、PPPoE、CAN又は他の既存プロトコルを要求する場合は、仕様の適用範囲を確認し、対応する既存スタックまたはコントローラーを優先して利用する。

プロトコル名の一部だけを使った独自形式を、そのプロトコルに対応していると表現しない。

## 3. フレーム境界の設計

フレーム方式は、入力がバイトストリームかメッセージ単位か、必要な再同期性、最大フレーム長、許容できる転送量、実行環境のCPU負荷及び相互運用相手を比較して決める。

平均的な入力だけでなく、予約バイトが連続する入力、最大長の入力及び通信エラー後の入力を評価する。

| 方式 | 適用しやすい入力 | 性質 | 注意点 |
| --- | --- | --- | --- |
| 長さフィールド | 最大長を明確にできるバイトストリーム | 予約バイトの出現による転送量の増加がない。 | 壊れた長さをそのまま信頼せず、上限、形式及び誤り検出を確認して再同期する。 |
| 区切り文字とエスケープ | 単純なストリーム分割と再同期を優先するバイトストリーム | 区切り文字を受信すれば次のフレーム境界を判断できる。 | 予約バイトの出現数に応じて転送量が増え、最悪時の増加量を別に評価する。 |
| COBS | 1個の予約バイトと一定の上限オーバーヘッドを使えるバイトストリーム | データ中に予約バイトを出さず、最悪時の増加量を小さくできる。 | COBSは符号化方式であり、誤り検出、バージョン、長さ、再送及び認証を提供しない。 |
| 下位層のメッセージ境界 | CANフレーム、UDPデータグラムなど | 追加のフレーム境界を実装しない。 | 上位メッセージの分割、順序、再構成及び欠落を別途定義する。 |

### 長さフィールドを使う

長さフィールドを使う場合は、ヘッダーを読んだ時点で最小長と最大長を検証し、上限を超える値のために無制限のメモリを確保しない。

長さ、種別、バージョン又は検査値が不正な場合に、次のフレームをどの位置から探索するかを定義する。

### 区切り文字とエスケープを使う

区切り文字とエスケープを使う場合は、エンコード前後の値、エスケープ対象、フレーム開始と終了、空フレーム及び不正なエスケープ列の扱いを定義する。

SLIPはシリアル回線のフレーム境界だけを定め、アドレス、種別及び誤り検出を提供しないため、これらを要求するシステムではSLIPの上に別途定義する。

PPPの非同期HDLC-like framingを使う場合は、フラグ`0x7e`、Control Escape`0x7d`、ACCM、FCSの計算対象とエスケープの順序及びフレーム破棄条件をRFC 1662に合わせる。

これはPPPのフレーム化方式であり、ISO/IEC 13239で定義されるHDLC手順全体や、RFC 1661で定義されるPPP全体と同一ではない。

### COBSを使う

COBS（Consistent Overhead Byte Stuffing）を使う場合は、予約する区切りバイト、エンコード済みデータ、フレーム終端及び空データの表現を固定する。

COBSの原論文が示す最大オーバーヘッドは、エンコード前のデータ254バイトにつき1バイトであり、フレーム終端の区切りバイトはこの増加量とは別に数える。

COBSのデコードは、コード値が示す範囲を入力の残り長さと最大フレーム長で検証し、終端を越える参照、整数オーバーフロー及び不正なコード列を受け入れない。

COBSだけではデータの破損を検出できるとは限らないため、伝送誤りを検出する場合は、COBSの入力側または出力側でCRC、MAC又はその他の検査値を組み合わせる。

## 4. フレーム内容の設計

フレーム形式は、フィールドの順序、長さ、値の範囲、バイトオーダー、検査範囲、最大長及び異常時の処理を一つの仕様として定義する。

実装者がソースコードを読まなくても、任意のバイト列に対する判定結果を決められる状態にする。

| フィールド | 定義する内容 |
| --- | --- |
| 同期または開始情報 | フレームの開始を検出する値、ビット列又は下位層の境界。 |
| バージョン | 対応する形式、未知の値を受け取ったときの処理及び互換性の範囲。 |
| 種別 | ペイロードの解釈方法、予約値及び未知の値を受け取ったときの処理。 |
| 長さ | 長さが表す範囲、単位、最小値、最大値及びヘッダー・検査値を含むかどうか。 |
| 識別または順序 | アドレス、チャネル、シーケンス番号及び重複・欠落・順序逆転の扱い。 |
| ペイロード | エンコード前後の位置、形式、最大長及び空データの扱い。 |
| 誤り検出または認証 | CRC、FCS、MACなどの方式、初期値、係数、反映、XOR、バイトオーダー、検査範囲及び失敗時の処理。 |

複数バイトのフィールドは、フィールドごとにバイトオーダーを明記し、実行環境のネイティブ表現へ依存しない。

言語の構造体をそのままバイト列へ変換せず、パディング、アラインメント、整数表現及び未初期化領域が通信形式へ入らないようにする。

長さ、種別、バージョン及び検査値を確認してからペイロードを上位処理へ渡す。

CRCまたはFCSは偶発的な伝送誤りの検出に使い、攻撃者による改ざん、なりすまし又は機密性の保護にはMAC、署名又は暗号化を別途設計する。

## 5. ストリーム解析とバッファ管理

### 入力を塊で受け取り、解析状態を保持する

ストリーム解析器は、入力の分割位置によらず同じ結果を返す。

外部APIは利用可能な入力を`&[u8]`などの塊で受け取れる形にし、解析途中の状態を次回の呼び出しへ保持する。

解析アルゴリズムがバイト単位の状態遷移を必要とする場合でも、呼び出し元が1バイトごとに読み取り、システムコール、ロック取得、タスク起動又はメモリ確保を繰り返す構造にはしない。

UART FIFO、DMA、リングバッファ又はソケットの読み取りで取得した入力塊を、解析器の内部で順に処理する。

状態遷移が必要な方式では、決定性有限オートマトン（DFA）または同等の状態機械として、状態、入力条件、次状態、蓄積するデータ、エラー状態及び再同期方法を明記する。

不正な入力、フレーム長超過、入力の終了、タイムアウト及び通信切断のそれぞれで、解析器が保持する状態と破棄するデータを定義する。

### 上限とコピーを管理する

受信バッファ、フレーム長、キュー件数及び未処理入力の上限を定め、上限を超えた場合は上位処理へ渡さず、定義したエラーまたは再同期へ移行する。

入力を受信するたびに無制限にバッファを拡張しない。

ペイロードをコピーせずに参照できる場合は、参照元のバッファが有効な期間をAPIで表現し、その期間を越えて参照を保持できないようにする。

保持期間を延ばす必要がある場合は、必要な箇所で一度だけ所有バッファへコピーし、コピー回数と対象サイズを測定できるようにする。

## 6. 性能と転送量の検証

性能の評価は、入力を1バイトずつ処理するかどうかだけで決めず、転送量、読み取り回数、CPU時間、メモリ確保回数、コピー量、待ち時間及びエラー時の回復時間を測定する。

通信速度、CPU、入力サイズ、入力内容、同時実行数及び測定区間を固定して比較できる状態にする。

エスケープ方式は、予約バイトが現れない入力、予約バイトだけの入力、すべてのバイト値を含む入力及び最大長の入力を測定する。

COBSは最悪時の増加量を上限として評価し、区切り文字の1バイトを含めて送信フレーム長を計算する。

PPPのオクテットスタッフィングはACCMとエスケープ対象を含めて評価し、平均値だけで最大転送時間を見積もらない。

送信側は、フレームごとに必要な最大バッファ長、分割送信の回数及びコピー回数を明らかにする。

受信側は、読み取り塊の大きさ、解析の処理量、破棄した入力の量及び再同期までの時間を記録する。

## 7. 誤り、タイムアウト及び再接続

検査値の失敗、形式不正、長さ超過、未知のバージョン、未知の種別、キュー満杯及び入力の途中終了を区別して記録する。

エラーの記録には、機密情報を含むペイロード全体を無条件に出力せず、発生数、フレーム長、状態及びエラー種別を使う。

フレームの受信待ち、応答待ち、送信待ち及び再接続待ちには、通信方式に対応した期限を定義する。

途中まで受信したフレームが期限を超えた場合は、保持中のデータを破棄し、次のフレームを検出できる状態へ戻す。

再送を行う場合は、要求の識別子、応答の識別子、再送回数、再送間隔、重複受信、応答の遅延及び最終的な失敗を定義する。

受信側は、同じ要求を複数回処理しても安全な冪等性を持たせるか、重複を識別して一度だけ処理する。

通信切断やセッションの終了後に再接続する場合は、古いフレームの解析状態、シーケンス番号、応答待ち、再送キュー及び認証状態を引き継ぐか破棄するかを定義する。

再接続を繰り返す場合は、固定間隔で集中させず、上限付きの指数バックオフとジッターを使う。

## 8. 標準方式の適用判断

次の表のように、方式を層または観点へ対応付けて扱う。

| 層または観点 | 用語 | 本書での扱い |
| --- | --- | --- |
| データリンク層の手順 | HDLC（High-Level Data Link Control） | ISO/IEC 13239が定めるデータリンク層の手順を指す。HDLC互換を要求された場合は、対象のクラス、フレーム形式、透明性、FCS及び手順を特定する。PPPのHDLC-like framingをHDLC全体と同一視しない。 |
| ポイントツーポイントのリンクプロトコル | PPP（Point-to-Point Protocol） | RFC 1661が定める、カプセル化、LCP、NCP及び関連するリンク運用を含むプロトコルを指す。非同期シリアルのフレーム化だけが必要な場合は、PPPと呼ばず、必要なフレーム方式を明記する。 |
| Ethernet上のカプセル化 | PPPoE（Point-to-Point Protocol over Ethernet） | RFC 2516が定めるEthernet上のPPPセッション確立及びカプセル化を指す。UART、RS-232又は一般的なバイトストリームのフレーム方式として採用しない。 |
| データリンク層及び物理符号化サブレイヤー | CAN（Controller Area Network） | ISO 11898-1が定める方式を指す。CANコントローラーやSocketCANが提供するフレーム境界、識別子、調停及びエラー処理を利用し、UART用の区切り文字方式を重ねない。 |
| バイトストリームのフレーム境界 | SLIP（Serial Line IP） | RFC 1055が定めるシリアル回線のフレーム境界を指す。SLIPはアドレス、種別及び誤り検出を提供しないため、それらが必要な場合は別途定義する。 |
| バイトストリームの符号化 | COBS（Consistent Overhead Byte Stuffing） | 予約バイトをデータから除外する符号化方式を指す。フレーム境界の補助であり、通信相手、誤り検出、再送、認証又は暗号化を定義するプロトコルではない。 |

既存プロトコルへ対応する場合は、実際の実装で使用されている受信塊、状態、バッファ上限、検査失敗及びフロー制御の扱いを確認し、仕様と実装の差を相互運用テストで検出する。

標準仕様にない独自の短縮、フィールド省略又はエラー処理を相手へ暗黙に要求しない。

## 9. 検証

通信プロトコルのテストは、期待するフレーム、メッセージ及び状態を仕様から作成し、実装の内部手順をそのままテストへ写さない。

[テストガイドライン](../software/testing-guidelines.md)に従い、正常系、境界及び異常系を分けて検証する。

| 検証対象 | 確認する入力または状態 |
| --- | --- |
| 入力分割への独立性 | 完全なフレーム、任意位置で分割した入力、1バイトずつの入力及び複数フレームをまとめた入力。 |
| フレーム境界 | 空フレーム、連続する区切り文字、開始直後の終了、終端なし、未知の予約値及び通信ノイズ後の入力。 |
| フレーム形式 | 最小長、最大長、上限の前後、未知のバージョン、未知の種別、各バイトオーダー及び予約値を含むペイロード。 |
| COBS | 空データ、254バイト境界の前後、ゼロを含まない最大長、ゼロが連続する入力、不正なコード値、終端不足及び終端後の余分な入力。 |
| エスケープ方式 | 予約バイトを含まない入力、予約バイトだけの入力、連続するエスケープ、不正なエスケープ列及び最大オーバーヘッド。 |
| 誤り検出 | ヘッダー、ペイロード及び検査値の各ビット反転、検査範囲の境界、誤った初期値、誤ったバイトオーダー及び長さ不一致。 |
| 回復 | フレーム長超過、キュー満杯、タイムアウト、切断、再接続、重複要求、欠落した応答及び順序逆転。 |
| 性能 | 読み取り塊のサイズ、最大フレーム、最悪のエスケープ量、CPU時間、確保回数、コピー量、処理遅延及び再同期時間。 |
| 相互運用 | 対応する標準仕様の実装、異なる送受信塊、最大長、検査エラー、フロー制御及び再接続。 |
