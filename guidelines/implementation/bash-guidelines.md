## 1. 概要

本書は、Bash 3.2以上で動作するシェルスクリプトと、`source`して利用する関数ライブラリの実装ガイドラインを定義する。本書は、[ソフトウェア設計ガイドライン](../software/software-design-guidelines.md)と[Shell Style Guide](https://google.github.io/styleguide/shellguide.html)を前提とする。

本書は言語に固有の規則だけを定義する。プロジェクトが公開する関数の一覧、コマンドライン引数の仕様、特定サービス向けの処理は、利用側プロジェクトの仕様として定義する。

---

## 2. バージョン互換性

macOSに同梱されるBashは3.2であり、Bash 4以降を前提としたスクリプトはmacOSでそのまま動作しない。macOSとLinuxの両方で動作させるスクリプトは、Bash 3.2で解釈できる構文と機能だけを使用する。

Bash 4以降で追加された次の機能は使用しない。

| 機能 | 構文 | 追加バージョン |
| --- | --- | --- |
| 連想配列 | `declare -A` | 4.0 |
| ファイルから配列への読み込み | `mapfile`、`readarray` | 4.0 |
| 大文字小文字変換 | `${var^^}`、`${var,,}` | 4.0 |
| 再帰的なパス展開 | `globstar`、`**` | 4.0 |
| 後続パターンの継続評価 | `case`の`;;&` | 4.0 |
| コプロセス | `coproc` | 4.0 |
| 変数の参照 | `local -n`、`declare -n` | 4.3 |

シェバンは`#!/usr/bin/env bash`とし、`bash`のパスとバージョンを固定しない。

OS名やCPUアーキテクチャで分岐せず、実際に依存する機能またはコマンドの有無で分岐する。

## 3. シェルオプション

`set -e`、`set -u`、`set -o pipefail`は、実行スクリプト自身が冒頭で設定する。

```bash
#!/usr/bin/env bash

set -euo pipefail
```

`source`して利用する関数ライブラリでは、これらを設定しない。シェルオプションは呼び出し元シェル全体の状態であり、ライブラリが変更すると、ライブラリと無関係なコードの動作まで変わる。ライブラリ関数は、呼び出し元のシェルオプションの設定状態に依存せずに動作するように実装する。

---

## 4. 関数

関数は`<name>() { ... }`の形式で定義し、`function`キーワードを使用しない。

`source`して利用する関数ライブラリの関数には、名前空間を付ける。

```text
<domain>::<action>
```

```text
string::upper
path::normalize
```

名前空間は機能領域を表し、末尾は処理を表す動詞または動詞句とする。2階層で意味が十分な場合は2階層とし、必要な場合だけ3階層以上にする。

関数内の変数は`local`で宣言し、呼び出し元のスコープを汚さない。コマンドの出力を代入する場合は、宣言と代入を分ける。`local`は自身が成功するため、宣言と代入を1文で書くとコマンドの終了ステータスが失われる。

```bash
string::upper() {
    local value=$1
    local result

    result=$(printf '%s' "$value" | tr '[:lower:]' '[:upper:]') || return 1

    printf '%s\n' "$result"
}
```

## 5. 引数

引数の解析方法は、公開するインターフェースの形式に合わせて選ぶ。

| 形式 | 例 | 解析方法 |
| --- | --- | --- |
| 短いPOSIX形式のオプション | `-n VALUE`、`-f` | Bash組み込みの`getopts`を使用する。 |
| 複数文字の名前付き引数 | `--name VALUE`、`--force` | Bashの`while`と`case`で解析する。 |

外部コマンドの`getopt`は使用しない。macOSに同梱されるBSD版はロングオプションを解釈せず、GNU版との差分が移植性の問題になる。

`while`と`case`で解析する場合は、各引数の値をローカル変数へ明示的に代入する。値を取る引数では、値が指定されていることを残りの引数の数で検査する。

```bash
user::create() {
    local name=''
    local shell='/bin/sh'
    local force='false'

    while [ "$#" -gt 0 ]; do
        case $1 in
            --name)
                if [ "$#" -lt 2 ]; then
                    printf 'Error: Option %s requires a value.\n' "$1" >&2
                    return 1
                fi
                name=$2
                shift 2
                ;;
            --force)
                force='true'
                shift
                ;;
            *)
                printf 'Error: Unknown option %s.\n' "$1" >&2
                return 1
                ;;
        esac
    done

    # 処理
}
```

引数からローカル変数への対応が`case`を読めば分かる状態を維持し、解析処理を隠蔽する仕組みを作らない。ローカル変数への動的な代入を目的として`eval`を使用しない。

## 6. 入力検査

公開する関数とスクリプトは、処理を開始する前に入力を検査する。必須値、数値、パス、列挙値、依存するコマンドの存在を検査対象に含める。

検査を行う関数は、`validate::`のように用途が分かる名前空間へまとめる。

---

## 7. エラー処理

`source`して利用する関数ライブラリの関数は、回復不能なエラーでも`exit`せず、非0の終了ステータスを`return`する。対話型シェルから読み込まれた場合、`exit`は利用者のシェルそのものを終了させる。

エラーメッセージは標準エラー出力へ出力する。標準出力は関数の結果を渡す経路として空けておく。

---

## 8. OS差分

macOSとLinuxで外部コマンドの有無やオプションに差がある場合は、その差分をユーティリティ関数の内部で吸収し、呼び出し側へ露出させない。

GNU版とBSD版で挙動が異なる外部コマンドへ依存する前に、Bashの組み込み機能だけで実現できないか検討する。

外部コマンドが必要な場合は、その機能を実際に使用する時点で存在を確認する。

---

## 9. 外部依存

標準的なBashの機能だけで実装できる処理に、外部のシェルスクリプトライブラリを追加しない。

外部依存を採用するのは、Bash 3.2の機能だけでは合理的に実装できず、保守性または利用者体験が明確に改善する場合に限る。

---

## 10. 読み込み時の副作用

`source`しただけで、呼び出し元の環境を書き換えない。次のものを読み込み時に変更しない。

- シェルオプション
- `IFS`
- カレントディレクトリ
- 既存のエイリアス
- ライブラリと無関係な環境変数

関数の定義など、ライブラリを利用するために必要な定義は読み込み時に行う。

## 11. 検証

実行コマンドは、各プロジェクトで定義する。

| 目的 | 検証対象 | ツール |
| --- | --- | --- |
| Bash 3.2で解釈できることを確認する。 | 構文エラー。 | `bash -n` |
| 静的な不具合と移植性の問題を検出する。 | シェルスクリプト全体。 | ShellCheck |
| 関数単位の振る舞いを検証する。 | 正常系と異常系。 | Bats-core |
| 対応環境での実行を確認する。 | macOSとLinuxそれぞれの実行結果。 | 対応するOSでのCI実行 |
