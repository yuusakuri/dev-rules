# 地図アプリケーション設計ガイドライン

## 1 はじめに

### 1.1 目的

本書の目的は、大量の地理データを、滑らかな操作及び速い読込みで表示するための判断基準を共有することである。

### 1.2 適用範囲

本書は、Webアプリケーション及びモバイルアプリケーションでの地図の表示方式、地理データの配信、描画の性能、操作性及び外部の地図データの利用について規定する。

本書は、[アーキテクチャ設計ガイドライン](architecture-guidelines.md)及び[Webアーキテクチャガイドライン](web-architecture-guidelines.md)を前提とする。地図の周囲の画面の視覚表現は、[Web UIガイドライン](../ui/web-ui-guidelines.md)による。

### 1.3 用語及び定義

本書で用いる主な用語及び定義は、[表1](#table-1)によるほか、[アーキテクチャ設計ガイドライン](architecture-guidelines.md)による。

<a id="table-1"></a>表1−用語及び定義

| 用語 | 定義 |
| --- | --- |
| 地物 | 地図上に表示する点、線又は面の一つ一つ。 |
| ズームレベル | 地図の縮尺を示す段階。値が1増えるごとに、縮尺が2倍になる。 |
| タイル | 地図を、ズームレベルごとに格子状に分割した区画。`z/x/y`で位置を表す。 |
| ベクタタイル | 地物の形状及び属性をタイルごとに格納したデータ。描画はクライアントで行う。 |
| MVT（Mapbox Vector Tile） | ベクタタイルをProtocol Buffersで符号化する形式の仕様。 |
| PMTiles | 全てのタイルを一つのファイルにまとめ、HTTPの範囲要求で必要なタイルだけを読む形式。 |
| GeoJSON | 地物をJSONで表す形式。RFC 7946で定義される。 |
| 空間索引 | 位置の範囲で地物を高速に検索するための索引。 |
| クラスタリング | 近くにある複数の点を、一つの集約した点として表示する処理。 |
| 表示範囲 | 画面に表示している地図の範囲。南西及び北東の座標で表す。 |
| WGS 84（EPSG:4326） | 緯度及び経度で位置を表す座標参照系。 |
| Webメルカトル（EPSG:3857） | Webの地図で広く使われる投影法による座標参照系。 |

## 2 表示方式の選択

### 2.1 データ量による選択

表示方式は、表示範囲に入る地物の数及び更新の頻度から、[表2](#table-2)によって選ぶ。地物の数の区分は目安であり、対象の端末で描画のフレームレート及び読込み時間を測定して確定する。

<a id="table-2"></a>表2−データ量による表示方式の選択

| 地物の数及び更新の頻度 | 表示方式 | 性能上の理由 |
| --- | --- | --- |
| 数百件以下 | GeoJSONを一度に読み込み、WebGLのレイヤーで描画する。 | 読込みが1回で済み、操作中の通信がない。 |
| 数千件〜数万件の点 | GeoJSONを読み込み、クライアントでクラスタリングして描画する。クラスタリングは、Web Workerで行う。 | 描画する点の数がズームレベルに応じて減り、主スレッドを占有しない。 |
| 数十万件以上、又は大量の頂点をもつ線及び面 | ベクタタイルを事前に生成し、PMTilesなどの形式でCDNから配信する。 | 表示範囲のタイルだけを読み、ズームレベルに応じて形状が単純化される。 |
| 数十万件以上で、頻繁に更新される | データベースから要求ごとにベクタタイルを生成し、短い期限でCDNにキャッシュする。 | 更新をすぐに反映しつつ、同じタイルの再生成を避ける。 |
| 数百万件以上の点を、集約せずに表示する | GPU（Graphics Processing Unit）で直接描画するライブラリ（deck.glなど）を使い、バイナリ形式でデータを渡す。 | 地物ごとの処理を、GPUで並列に行う。 |
| 密度、分布など、個々の地物より傾向を示す | ヒートマップ、又は六角形の格子（H3など）で集計した値を描画する。 | 描画する図形の数が、地物の数ではなく格子の数で決まる。 |

### 2.2 DOMのマーカーを使わない

地物は、HTMLの要素（DOMのマーカー）ではなく、WebGLのレイヤーで描画する。DOMの要素は、地図の移動のたびに位置を再計算するため、数が増えると操作が滑らかでなくなる。DOMのマーカーは、選択中の地物、現在地など、数件の特別な表示にだけ使う。

### 2.3 描画ライブラリを選ぶ

描画ライブラリは、WebGLでベクタタイルを描画するもの（MapLibre GL JSなど）を既定とする。数百万件以上の点の描画、又は3次元の可視化が必要な場合は、deck.glなどのGPUで描画するライブラリを重ねて使う。

## 3 データの配信

### 3.1 データを小さくする

配信するデータは、次によって小さくする。

- 描画に使わない属性を除く。詳細な属性は、地物を選択したときにIDで取得する。

- 座標の小数点以下の桁数を、表示に必要な精度に丸める。小数点以下6桁で、約0.1 mの精度がある。

- 線及び面の形状は、ズームレベルごとに単純化する。

- 低いズームレベルでは、小さな地物を除くか、集約する。

- 応答は、Brotli又はgzipで圧縮する。

### 3.2 表示範囲のデータだけを取得する

ベクタタイルを使わずにAPIから地物を取得する場合は、表示範囲及びズームレベルを条件に、範囲内のデータだけを取得する。地図の移動が止まってから要求を送り、移動中に送った古い要求は取り消す。取得済みの範囲は、クライアントでキャッシュする。

### 3.3 空間索引を使う

地理データは、空間索引をもつデータベース（PostGISなど）に保存し、範囲の条件で検索する。空間索引がなければ、全ての地物を走査することになり、件数に比例して遅くなる。

座標は、WGS 84で保存する。距離及び面積は、測地線で計算する型又は適切な投影法で計算し、Webメルカトルの座標で計算しない。Webメルカトルでは、緯度が高いほど距離及び面積が拡大される。

### 3.4 タイルをキャッシュする

ベクタタイル及びラスタのタイルは、CDNでキャッシュする。事前に生成したタイルは、データの版をURLに含め、無期限にキャッシュする。要求ごとに生成するタイルは、データの更新の頻度に合わせた期限でキャッシュする。

## 4 描画の性能

描画の性能は、次によって確保する。

- 同じ種類の地物は、レイヤーを分けず、データの属性による描き分けで一つのレイヤーにまとめる。レイヤーの数が増えるほど、描画の処理が増える。

- レイヤーに、表示するズームレベルの範囲を設定し、必要のないズームレベルで描画しない。

- 選択、ホバーなどの表示の変更は、データの再読込みではなく、地物の状態の更新で行う。

- データの解析、クラスタリング及び座標の変換などの重い処理は、Web Workerで行う。

- 描画のフレームレート、タイルの読込み時間及びメモリの使用量を、対象とする最も性能の低い端末で測定する。

## 5 操作性

### 5.1 最初の表示

最初の表示範囲は、利用者の目的に関係するデータの範囲に合わせる。現在地は、利用者が現在地のボタンを押したときに取得し、ページを開いた直後には位置情報の許可を求めない。位置情報の許可が拒否された場合も、地名の検索などで目的の場所へ移動できるようにする。

### 5.2 データの量及び状態を示す

データの量及び状態は、次によって示す。

- 読込み中は、地図の上に読込み中の表示を出す。

- 低いズームレベルで地物を集約又は省略している場合は、拡大すると表示されることを示す。

- 表示範囲に該当する地物がない場合は、その旨と、条件の変更方法とを示す。

- 集約した点を選択した場合は、含まれる地物が個別に表示されるズームレベルまで拡大する。

### 5.3 一覧と地図とを連動させる

地図と一覧とを並べる場合は、表示範囲に入る地物を一覧に表示し、一覧と地図との選択を連動させる。狭い画面では、一覧を、地図の下から引き出す領域に表示する。

### 5.4 地図の状態をURLに持たせる

地図の中心、ズームレベル、選択中の地物及び絞込みの条件は、URLに持たせる。理由及び方法は、[Webアーキテクチャガイドライン](web-architecture-guidelines.md)の4.3による。

### 5.5 ページのスクロールを妨げない

縦にスクロールするページの中に地図を埋め込む場合は、1本指の操作ではページをスクロールし、2本指の操作又は修飾キーとの組合せで地図を移動させる。

### 5.6 地図以外の手段でも情報を提供する

地図だけでは、画面読み上げの利用者が情報を得られない。地図に表示する地物は、一覧又は表でも提供する。地図の操作のボタンは、キーボードで操作できるようにする。地物の種類は、色だけでなく、形又は記号でも区別する。

## 6 外部の地図サービス及びデータの利用

外部の地図サービス及びデータは、次によって利用する。

- 背景地図のタイルは、利用条件が大量の利用を許す提供元から取得するか、自ら生成して配信する。OpenStreetMapの公式のタイルサーバーは、大量の利用を禁止している。

- 地図データの提供元が求める出典を、地図の上に表示する。OpenStreetMapのデータには、ODbL（Open Database License）に基づく出典の表示が必要である。国土地理院の地理院タイルには、出典の表示が必要である。

- 外部の地図サービスのAPIキーは、利用できるドメイン又はアプリケーションを制限する。

- 外部の地図サービスの料金が、地図の読込み回数又はタイルの要求数で決まる場合は、利用条件が許す範囲でキャッシュし、要求を減らす。

## 7 チェックリスト

- 表示範囲に入る地物の数及び更新の頻度から、[表2](#table-2)で表示方式を選び、対象の端末で測定している。

- 大量の地物を、DOMのマーカーで描画していない。

- 描画に使わない属性を配信していない。

- 座標の精度を、表示に必要な桁数に丸めている。

- 地理データを、空間索引で検索している。

- 距離及び面積を、Webメルカトルの座標で計算していない。

- タイルを、CDNでキャッシュしている。

- 重い処理を、Web Workerで行っている。

- 地図の状態が、URLに含まれている。

- 地図に表示する地物を、一覧又は表でも提供している。

- 地図データの出典を表示している。
