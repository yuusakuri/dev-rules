# ドキュメント作成ガイドライン

本書は、文書の文体、説明の組み立て方、根拠の示し方、参考資料の表の作り方を定めます。

## 文体

日本語として自然な文体で書き、読者へ話しかけるような丁寧な文で説明します。

述語と目的語を省かずに書きます。読者は、誰が何をするのかを補って読む必要がなくなります。

## 表記

絵文字は使わず、比喩にも頼らずに、事実をそのまま書きます。

強調の書式と太字は使いません。読み手が注目する箇所は、見出しと文章の並び順で示します。

専門用語は不自然に和訳せず、その分野で一般的かつ正確な表記を使います。ただし、短い専門用語を並べるだけで済ませず、平易な言葉で意味を補います。

## 文の区切り

1文は1行で完結させます。文の途中でコードブロックや引用ブロックを挟むと文が分断されるため、文を書き終えてからブロックを置きます。

## 説明の組み立て

箇条書きや列挙だけで済ませず、通して読める文章で説明します。

守るべき事柄を説明するときは、どのような場合に、何をして、その結果どうなるのかを、必要な範囲で3文以内にまとめます。常に当てはまる事柄では、どのような場合かを省きます。「条件」「目的」「理由」「ルール」といった言葉は文中で直接使わず、内容そのものを書きます。

見出しや表など他の記載項目から読み取れる事柄は、説明として繰り返しません。

## 名前の付け方

「共通」「基本」のような、扱う対象を絞り込めない名前は付けません。何を扱うのかが分かる名前を付けると、読者は目次だけで必要な章を選べます。

## 記述量

同じ意味の言い換えを重ねず、正確に、簡潔に、体系的に書きます。

似た内容が続く箇所でも省略せず、すべての項目を同じ細かさで書き切ります。

## 記載する範囲

変更の過程、検討の経緯、今後の予定は書かず、確定した内容だけを体系的に記述します。「追加予定」「廃止」のような記述が残っていると、読者はその文書がどの時点の状態を表すのか判断できなくなります。

細かな前提や方針は、記載を求められた場合に限って書き、それ以外は必要最小限にとどめます。

安全のために何をしなかったか、どのような工夫をしたかといった書き手の事情は書きません。「ご提示いただいた条件に基づき」のような前置きと、読みどころをまとめた後書きも置かず、読者が求める内容だけを残します。

課題への対処を書くときは、その場をしのぐ回避策ではなく、原因を取り除く方法を書きます。

## 根拠

記述する内容には根拠を持たせます。推測、第三者が書いた記事、Q&Aサイトの投稿のような、信頼性を確かめられない情報は根拠にしません。

根拠には、次のいずれかに当たる資料を使います。

| 資料 | 例 |
| --- | --- |
| 提供元による公式資料 | 製品、サービス、技術の提供元が公開する文書 |
| 標準仕様 | RFC、W3C、WHATWG、ISO、IEEEなどの仕様書 |
| 組織の公式資料 | 公的機関、大手企業、業界組織、学術機関が公開する文書 |
| 原著論文 | 研究成果を最初に発表した論文 |
| 百科事典 | Wikipedia |
| OSSの公式資料 | 著名なOSSが公開する文書 |

これらに当たる資料が見つからないときは、利用できる中で最も信頼性の高い資料か、実際に試して確認した結果を根拠にします。

使った資料は本文の途中では示さず、参考資料の章にまとめます。

## 仕上げの確認

書き終えた文書は、粗を探すレビュアーの視点で読み返し、根拠の弱い記述と曖昧な表現を直します。自分で判断できない箇所が残るときは、修正案を添えて関係者へ相談します。

## 参考資料の表

### 章の位置

参考資料は、文書の最後のH2見出し「参考資料」へまとめます。

章に番号を振っている文書では、直前の章に続く番号を見出しへ付けます。

### 列の構成

表には`本書の章`、`参考資料`、`説明`の3つの列を設けます。

`本書の章`には、その資料を使った箇所をH2見出しの単位で書きます。H3以下の見出しは挙げません。

`説明`には、その資料から何が分かるのかを簡潔に書きます。

### 行の分け方

参考資料は、資料1件につき1行とします。同じ章で複数の資料を使うときも、資料ごとに行を分けます。

1件の資料が複数の章にかかるときは、その行の`本書の章`セルへ、見出しのタイトルを`<br>`で区切って並べます。

### 資料の選び方

必要な情報が1つのページに収まっているときは、節や項ごとのURLへ分けず、そのページを1件として挙げます。

同じ資料に日本語版のページがあるときは、日本語版のURLを記載します。
