## 1 はじめに

### 1.1 目的

本書の目的は，技術文書の一貫性，明瞭性及び正確性を確保することである。

### 1.2 適用範囲

本書は，技術文書の作成方法について規定する。

ただし，別の様式又は構成を用いることが適切な技術文書及びその部分には適用しない。

注記1 JIS Z 8301 : 2019 規格票の様式及び作成方法，ISO/IEC Directives, Part 2，ISO 24495-1:2023及び公用文作成の考え方（文化審議会建議）を参考に作成した。

注記2 本書のひな形として，[技術文書テンプレート](../../templates/documentation/technical-document.md)がある。

注記3 文書の種類に固有の事項は，[リファレンス文書作成ガイドライン](reference-guidelines.md)，[解説文書作成ガイドライン](explanation-guidelines.md)及び[手順書作成ガイドライン](how-to-guidelines.md)を参照。

### 1.3 用語及び定義

この文書で用いる主な用語及び定義は，[表1](#table-1)による。

<a id="table-1"></a>表1−用語及び定義

## 2 一般原則

### 2.1 技術文書が満たす条件

技術文書は，次の条件を満たさなければならない。

a) 適用範囲に規定する範囲内で，必要な事項を規定している。

b) 一貫性があり，明瞭かつ正確である。

c) 作成に参加していない関係者にも理解可能である。

d) 読者が必要とする情報を含み，読者がその情報を容易に見つけ，理解し，利用することが可能である。

文書の分かりやすさは，読みやすさの公式などの機械的な指標ではなく，読者が文書を利用できたかどうかによって判断する。

### 2.2 計画及び準備

技術文書の作成に着手する前に，次に示す事項を明確にする。

- 技術文書の体系及び位置付け

- 関連する技術文書及び法規との相互関係

- 主題の構成及び区分け

確定していない記載事項がある場合は，依頼者又は文書の責任者に確認する。

文書の種類及び媒体は，読者の特性，目的及び読む状況に合わせて選ぶ。

文書を書き始める前に，分量の上限を決める。

書き終えた文書は見直し，必要性の低い内容を削る。

### 2.3 読者に合わせた平易さ

文書は，読者の知識，関心及び読解力に合わせた平易さで書く。

専門的な知識をもつ読者に向けた文書を，広く一般に向けた文書と同じ平易さにする必要はない。

### 2.4 一貫性

一つの技術文書の中及び関連する一連の技術文書の中では，読者の理解を助けるため，一貫性を保つことが望ましい。

そのため，次の事項によることが望ましい。

- 構成及び区分けの方法は，同じ形式とする。

- 同一の記述事項は，同じ表現を用いる。

- 一つの概念に対しては一つの用語を用い，同義語を用いない。

- 個々の用語には，一つだけの意味をもたせる。

一つの文書の中で，同じ語に複数の表記を混在させない。

表，箇条書き又は列挙で複数の対象を比較する場合は，比較する観点，説明の粒度，用語及び文の形式をそろえる。

同じ比較項目では，用途，構成要素又は提供範囲などの観点を混在させず，各対象について同じ範囲と詳しさで記載する。同じ意味の内容は，“提供する”などの述語及び列挙する順序もそろえる。

本文で示した比較項目は，表又は列挙の項目にも対応させる。各項目には，その項目名に対応する内容を記載する。

### 2.5 重複規定の回避

規定の重複及び不必要な類似規定は，避けることが望ましい。

主題について技術文書を作成する前に，適用可能な技術文書が既に存在しているかどうかを確かめなければならない。

ある箇所で規定した事項を別の箇所で規定する必要がある場合は，繰り返して記載せず，引用・参照することが望ましい（[6章](#6-引用参照)参照）。

### 2.6 概要

概要は，文書，章，資料などの内容を要約して記載する。

概要は，1文とする。

概要の文は，原則として80文字以内とする。

概要は，対象の全体を表す抽象度で記載し，具体的な事項を列挙しないことが望ましい。

準拠した文書，参考にした文書などの補足は，概要の文に続けて，又は改行して記載してもよい。

補足は，概要の文の数及び文字数に含めない。

例 技術文書のテンプレート。JIS Z 8301及びISO/IEC Directives, Part 2を参考に作成した。

### 2.7 記述する内容

内容は，読者の必要を優先して選ぶ。書き手の都合で記載する内容がある場合も，読者の必要を念頭に置く。

読者が答えを求める問いを洗い出し，その答えを記載する。

読者の特性，目的及び読む状況，並びに文書の種類に合う内容を選ぶ。

読者が必要としない内容は，記載しない。

多くの読者が共通して必要とする事項を優先して記載し，副次的な内容は，別の文書又は別のページに記載する。

読者が行動するのに必要な情報が欠けている場合は，補う。

例 “設定ファイルを編集する。” → “プロジェクトのルートにある `config.toml` を編集する。”

内容は，次によって選ぶ。

a) 正確な内容を選ぶ。

b) 偽りの内容及び誤解を招く内容を含めない。

c) 読者が知る必要のある内容を，隠したり省いたりしない。

分かりやすさを高めるために，内容の正確さを損なってはならない。

言い換え，要約又は例示をした箇所は，誇張した情報がないこと，及び必要な情報を省いていないことを確認する。

文書の目的に必要な範囲を超えて厳密さを求めることは避け，必要な情報の範囲を正確に書くことが望ましい。

文書の内容は，正確，簡潔かつ体系的に記載する。

同じ意味の言い換えは，重ねない。

類似する事項も，省略せずに全てを記載する。

作業中の変更内容，検討中の事項及び未確定の予定は記載せず，確定した内容だけを記載する。

前提は，文書の目的に必要な範囲だけを記載する。

課題への対処を記載する場合は，その場をしのぐ回避策ではなく，原因を取り除く方法を記載する。

何をしないか，どのような工夫をしたか，どのような規則を守ったかといった書き手の事情は，記載しない。

書き手が資料を参照した日付は，記載しない。

“ご提示いただいた条件に基づき”のような前置き，及び読みどころをまとめた後書きは，置かない。

### 2.8 説明の組立て

伝えるべき重要な事項は，はっきりと述べる。

読者にとって不利益となる事項を伝える場合も，周辺の事項又は例外から説明を始めない。

読者に察してもらわなければ伝わらない書き方は，しない。

説明が必要な箇所は，箇条書き又は表だけに頼らず，文章で補う。ただし，見出し又は表から読み取れる事項は，説明として繰り返してはならない。

守るべき事項は，どのような場合に何をし，その結果どうなるかを，必要最小限の文で記載する。

常に当てはまる事項では，どのような場合かを省略する。

“条件”，“理由”のようなラベルを多用するのは避け，その内容を文章で書くことが望ましい。

言葉だけでは分かりにくい内容は，図，表，写真，動画などで示す。

条件と値との組合せが複数ある内容は，表で示す。

対応関係，構造及び処理の流れは，文字を並べて描いた図ではなく，表又は図で示す。

抽象的な説明は，例で補う。

### 2.9 情報の順序

関連する情報はまとめ，読者にとって意味の通る順序で並べる。

情報の順序は，次による。

a) 最も重要な事項は，読者が見つけやすい位置に置く。通常は，冒頭に置く。

b) 結論を先に示し，理由及び詳細を続ける。

c) 新しい情報は，読者が既に知っている情報を基にして導入する。

d) 手順及び処理は，時間の順序に従って示す。

e) 多くの読者が必要とする情報は，一部の読者だけが必要とする情報よりも前に置く。

f) 手順に従わない場合に損害又は危害が生じるおそれがあるときは，してはならないことの警告を，手順の指示よりも前に置く。

g) 読者の利益又は不利益に関わる文書では，読者が進める手順に沿って示す。

読者に選択肢を示して一つを選ばせる場合は，選択肢の内容に重なりがないようにする。

### 2.10 見出し

“共通”，“基本”のような，扱う対象を絞り込めない見出しは付けず，何を扱うかが分かる見出しを付ける。

### 2.11 根拠

記述する内容には根拠をもたせる。扱う対象の事実を最も直接的に定義する一次資料を優先して根拠とする。推測，個人の投稿など，出所を確かめられない情報を根拠にすることは避ける。

根拠の候補は，次による。

- 製品，サービス又は技術の提供元による公式資料

- RFC，W3C，WHATWG，ISO，IEEE，JISなどの標準仕様

- 公的機関，大手企業，業界組織又は学術機関の公式資料

- 原著論文

- Wikipedia

- 著名なOSSの公式資料

これらが見つからない場合は，利用可能な中で最も信頼性の高い資料，又は実際に試して確認した結果を根拠とする。

根拠とした資料は，本文の途中では示さず，参考文献に記載する（[9章](#9-参考文献)参照）。

ただし，本文から参照させることが自然な場合は，本文にもリンクを記載する。

### 2.12 チェックリスト

書き終えた技術文書は，次の事項を満たさない箇所を修正する。

- 読者が必要とする情報があり，必要としない情報がない。

- 分かりやすさのために正確さを損なっていない。

- 矛盾がない。

- 文体が統一されている。

- 一文の論点が一つであり，長すぎる文がない。

- 主語と述語との関係及び係り受けが明確である。

- 二重否定，不要な受動態及び回りくどい表現がない。

- 説明のない専門用語，外来語及び略語がない。

- 用語の表記揺れがない。

- 表，箇条書き又は列挙による比較では，観点，説明の粒度，用語及び文の形式がそろい，本文の比較項目とも対応している。

- 表，箇条書き又は列挙でも，文として記載した箇所の文末には句点が付いている。

- 用語の定義には，句又は文のいずれで記載する場合も，末尾に句点が付いている。

- 同義の反復，重複した説明及び不作為の説明がない。

- 書き手の事情が書かれていない。

- 書き手が資料を参照した日付が書かれていない。

- 見出しと本文の内容とが一致している。

章及び節の見出しは，“5 要求事項”，“5.1 一般”のように，番号と題名とをスペースで区切って表記する。

強調のための太字は，用いない。

## 4 用字，用語及び略語

### 4.1 文章

文章は，漢字と仮名とを交ぜて書き，口語体で書く。

文体は，文書の種類に応じて，常体（である体）と敬体（です・ます体）とから選ぶ（[リファレンス文書作成ガイドライン](reference-guidelines.md)及び[解説文書作成ガイドライン](explanation-guidelines.md)参照）。

一つの文書の中では，常体と敬体とのどちらかに統一する。ただし，引用，従属節及び箇条書きの部分では，異なる文末を用いてもよい。

技術文書にふさわしい自然な文体で記載する。

漢語を用いて自然に表現できる場合は，和語よりも漢語を優先して使用する。

表現の選択例を[表4](#table-4)に示す。

<a id="table-4"></a>表4−表現の選択例

| 和語 | 推奨する表現 |
| --- | --- |
| 動かす | 実行する，起動する，稼働させる，移動する |
| 示す | 示す |
| 終える | 終了する，完了する |
| 始める | 開始する，起動する |
| 決める | 決定する，指定する，設定する，定義する |
| しやすくなる | …性が高まる，容易になる |
| 使う | 使用する，利用する |
| 待つ | 待機する |
| 変える | 変更する，変換する |
| 変わる | 変化する，変更される，遷移する |
| 探す | 検索する，探索する |
| 見つける | 検出する，発見する，特定する |
| 確かめる | 確認する，検証する，照合する |
| 調べる | 調査する |
| やり直す | 再試行する |

ただし，耳で聞いて分かりにくい漢語は，和語に言い換える。

例 “塵埃” → “ほこり”

“漢字1字＋する”の形の動詞（“模する”，“擬する”など）は，多用しない。

外国語の文書を基に書く場合も，不自然な直訳の文にしない。

意味を取るために必要な述語及び目的語は，省略しない。

一つの段落では，一つの話題だけを扱う。

段落の冒頭には，その段落で扱う話題を示す文を置く。

文と文との関係，及び段落と段落との関係は，接続詞及び指示語で示す。

絵文字は，用いない。

比喩は用いず，具体的に記載する。

専門用語は，不自然に和訳せず，その分野で一般的かつ正確な表記を用いる。

関係する法令又は基にする外国語の文書の表記に合わせる必要がある場合は，[4.1](#41-文章)〜[4.6](#46-外来語)によらなくてもよい。

### 4.2 用字

#### 4.2.1 一般

[4.2](#42-用字)で規定していない漢字，仮名遣い，送り仮名，外来語の表記，ローマ字のつづり方などの一般的な事項は，国が定める公用文の表記の基準（常用漢字表，現代仮名遣い，送り仮名の付け方，外来語の表記，ローマ字のつづり方，公用文作成の要領など）による。

#### 4.2.2 漢字

漢字の字種，音訓及び字体は，常用漢字表による。

常用漢字表にない漢字，及び常用漢字表にある漢字であっても表に示されていない読み方をするものは，原則として用いず，仮名で書く。

仮名で書くと意味が分かりにくい場合は，仮名の後に括弧を付けて，本来の漢字を示してもよい。

例 きょう（筐）体，ぜい（脆）弱，漏えい（洩），ひずみ（歪）

#### 4.2.3 仮名遣い

仮名遣いは，現代仮名遣いによる。

#### 4.2.4 送り仮名

送り仮名は，送り仮名の付け方及び公用文における送り仮名の基準による。

#### 4.2.5 分かち書き

分かち書きは，複合語であることを示す場合，仮名が続いて読みにくい場合，読み誤りやすい場合，又は読点を多用するとかえって語句の関係が分かりにくくなる場合に用いる。

分かち書きには半角スペースを用い，中点“・”で代用しない。

例1 ケース バイ ケース

例2 研磨布紙と といし とを用い…

### 4.3 用語

#### 4.3.1 一般

用語の表記は，公用文作成の要領による。

専門用語は，次の順で優先して用いる。

a) 用語を定めた規格に規定された用語

b) 当該技術文書に関連する規格などで規定された用語

c) 学術用語集などに記載された用語

一般に知られていない専門用語は，語の性質及び使う場面に応じて，[表5](#table-5)のいずれかによって扱う。

<a id="table-5"></a>表5−専門用語の扱い

| 扱い | 適用する場合 | 例 |
| --- | --- | --- |
| 言い換える | 厳密な概念を問題にしない場合，又はその用語でなくても意味を表せる場合 | “永続化する” → “保存する” |
| 説明を付けて使う | 日常語に言い換えると意味が損なわれ，かつ，読者にとって重要な意味をもつ場合 | “冪等性（同じ操作を何度実行しても結果が変わらない性質）” |
| 説明を添えて普及させる | 読者に今後定着させる必要がある場合 | “多要素認証（パスワードに加えて，スマートフォンなどの別の手段でも本人を確認する方法）” |

専門用語を説明する場合は，次による。

- 大まかな意味を先に示し，詳しい意味を後に示す。必要に応じて，関連する語との違いを示す。

- 語は知られていても意味が正しく知られていない語は，意味を明確に示す。

- 日常語と異なる意味で用いる語には，専門用語としての意味を添える。

例 “例外（プログラムの実行中に起きた異常を，処理を中断して呼出し元に知らせる仕組み）”

#### 4.3.2 “以上”，“以下”，“を超え”及び“未満”

“以上”及び“以下”は，その前にある数値を含める意味で用いる。

“を超え”（“超”）及び“未満”は，その前にある数値を含めない意味で用いる。

#### 4.3.3 “及び”，“並びに”及び“かつ”

複数の項目又は条件の全てを同時に含める意味で併記する場合は，“及び”でつなぐ。

三つ以上の項目を併記する場合は，各項目を読点で区切り，最後の二つの項目だけを“及び”でつなぐ。

“及び”でつないだまとまりを，更に大きなまとまりとしてつなぐ場合は，“並びに”を用いる。

例1 寸法及び質量並びにこれらの許容差

注記 “長さ及び直径の測定方法並びに判定方法”は，“長さ及び直径の測定方法”と“判定方法”とを表す。一方，“長さ及び直径の測定方法及び判定方法”は，測定方法と判定方法との両方が長さ及び直径に係ることを表す。

併記する項目の関係が複雑な場合は，“及び”などの前に読点を付けて区切りを明確にするのがよい。

“かつ”は，“しかも”の意味で，密接に関係する項目又は条件をつなぐ場合に用いてもよい。

例2 確実かつ簡単な方法によって…

述語で終わる句を“かつ”でつなぐ場合は，“かつ”の前後に読点を付ける。

例3 明確に識別し，かつ，差異を示す。

“日本語かつ英語の説明を記載する。”のように，一つのものが同時に二つの性質をもつことを求める意味にならない場合は，“かつ”を用いず，“日本語及び英語の説明を記載する。”のように書く。

併記の構成が複雑で紛らわしい場合は，箇条書きに分けて書くのがよい。

“及び”などで併記した最後の項目に，“など”，“その他”などを付けない。

“や”は，“及び”と“又は”とのいずれの意味かが曖昧であるため，用いない。

“及び”の意味で“と”を用いない。

#### 4.3.4 “と”

“と”は，二つの項目を比較する場合など，両者の関係を示す場合に用い，後ろの項目にも“と”を付ける。

例 試薬Aと試薬Bとを混合する。AとBとを比較する。AとBとの間

#### 4.3.5 “又は”

複数の項目又は条件のいずれかを選ぶ意味で併記する場合は，“又は”でつなぐ。

三つ以上の項目を併記する場合は，各項目を読点で区切り，最後の二つの項目だけを“又は”でつなぐ。

例 寸法，材料又は構造

併記する項目の関係が複雑な場合は，“又は”などの前に読点を付けて区切りを明確にするか，箇条書きに分けて書くのがよい。

“又は”などで併記した最後の項目に，“など”，“その他”などを付けない。

選択の意味で“あるいは”を用いない。

#### 4.3.6 “及び”と“又は”とが混在する場合

“及び”と“又は”とを一つの文で用いる場合は，読点で区切りを示し，誤解が生じないように書く。

例1 A又はB，及びC又はD（AとC，AとD，BとC又はBとDのいずれかの組合せ）

例2 A及びB，又はC及びD（AとBとの組合せ又はCとDとの組合せ）

#### 4.3.7 “及び／又は”

複数の項目について，全てを含む場合といずれかを選ぶ場合とを同時に表す場合は，“及び／又は”を用いる。

紛らわしい場合は，箇条書きに分けて書くのがよい。

例 “A法及び／又はB法によって…”は，次のいずれかによって…と書き換えてもよい。

a) A法及びB法

b) A法

c) B法

#### 4.3.8 “場合”，“とき”及び“時”

“場合”及び“とき”は，条件，原因，理由などを表すときに用いる。

条件が二重になる場合は，大きい条件に“場合”を，小さい条件に“とき”を用いる。

“時”は，時期又は時刻を明確に示す必要がある場合に用いる。

#### 4.3.9 “から”，“まで”及び“より”

“から”は時点，場所などの起点を，“まで”は終点を表し，いずれもその前にある数値などを含める。

“より”は，比較を表す場合だけに用い，その前にある数値などを含めない。

よりどころを表す場合は，“…により”ではなく“…によって”と書く。

#### 4.3.10 “なお”，“また”及び“ただし”

文頭の“なお”及び“また”は，補足的な事項を書く場合に用いる。

“ただし”は，除外例又は例外を書く場合に用いる。

“なお”，“また”及び“ただし”の前で改行するかどうかは，文意と段落の区切りとを考えて決める。

### 4.4 記述符号

#### 4.4.1 種類

文章に用いる符号は，区切り符号，引用符号，連続符号，繰返し符号，省略符号及び括弧とする。

#### 4.4.2 区切り符号

区切り符号には，句点“。”，読点としてのコンマ“，”，中点“・”及びコロン“：”を用いる。

斜線“／”は，“及び／又は”などを書く場合に用いる。

句点は，文の終わりに付ける。表，箇条書き又は列挙の中でも，文として記載する場合は，文末に句点を付ける。

用語の定義には，句の形式で記載する場合も，末尾に句点を付ける。箇条書き，例などを簡単な名詞句又は物の名称で記載する場合は，句点を付けない。

“例：”及び“出典：”に続く内容が名称，語句又はリンクだけの場合も，末尾に句点を付けない。文として記載する場合は，文末に句点を付ける。

読点は，語句の切れ目又は続きを明らかにするため，次の場合に付けるのがよい。

- “は”，“も”などを伴って主題を示す語の後

- 条件又は制限を表す語句の後

- 対等に並ぶ二つ以上の語句を“など”，“その他”などでまとめる場合

- 文頭に置いた接続詞の後

- “及び”，“又は”などの前後の切れ目を明確にする必要がある場合

- その他，読点がないと誤解を生じるおそれがある場合

中点は，読点で区切ると読みにくくなる場合に名詞を連結するため，又は題名，見出し及び表の中で名詞を連結するために用いるのがよい。

句の切れ目には読点を，語の切れ目には中点を用いるように使い分けるのがよい。

例 許容差・限界値の示し方は，…

中点でつないだ最後の語に“など”を付けず，中点と“及び”，“又は”などとを混用しない。

コロンは，式，図，表又は文章の中で用いる用語又は記号を説明する場合に，その用語又は記号の後に付ける。

#### 4.4.3 引用符号

引用符号は“ ”とし，語句又は文章を引用する場合，及び文字，記号，用語などを特に示す必要がある場合に用いる。

かぎ括弧“「 」”は，用いない。

#### 4.4.4 連続符号

連続符号は“〜”とし，“…から…まで”を表す場合に用いる。

連続符号で示す範囲には，前後の数値を含める。

単位を付ける数値の範囲では，“10 mm〜20 mm”のように，前後のいずれの数値にも単位記号を付ける。

#### 4.4.5 繰返し符号

繰返し符号は“々”とし，同じ漢字を続けて書く語に用いる。

#### 4.4.6 省略符号

省略符号は“…”とし，語句を省略する場合に用いる。

#### 4.4.7 括弧

括弧は，その前に書いた事項に対する条件，選択，限定，補足などを表す場合に用いてもよい。

括弧は，通常，丸括弧“（ ）”を用いる。

丸括弧を含む範囲を更に括弧でくくる場合は角括弧“［ ］”を用い，角括弧を含む範囲を更にくくる場合は亀甲括弧“〔 〕”を用いる。

### 4.5 数字

数字は，アラビア数字を用いる。

ただし，次の場合は，漢数字を用いるのがよい。

a) “ひとつ”，“ふたつ”のように読む場合

例1 三つ目きり，一つ

b) 数の意味が薄い場合

例2 一般用

c) 概数を表す場合

例3 十数倍

d) 大きな数で，アラビア数字のゼロを並べると分かりにくい場合

例4 2万回

e) 慣用となっている場合

例5 一酸化炭素，二等辺三角形，二乗

### 4.6 外来語

外来語は，片仮名で書き，外来語の表記の基準による。

外来語は，語の性質及び使う場面に応じて，[表6](#table-6)のいずれかによって扱う。

<a id="table-6"></a>表6−外来語の扱い

| 扱い | 適用する場合 | 例 |
| --- | --- | --- |
| そのまま使う | 日本語に十分定着している場合 | “ファイル”，“パスワード” |
| 言い換える | 漢語又は和語に置き換えた方が分かりやすい場合 | “エビデンス” → “根拠”，“アサインする” → “割り当てる” |
| 説明を付けて使う | 分かりやすく言い換えることが困難な場合 | “オンボーディング（新しく加わった人が業務に慣れるまでの支援）” |
| 句全体を言い換える | 日本語として定着する途上にあり，文脈によって意味が異なる場合 | “スコープを切る” → “対象範囲を決める” |

外来語の専門用語は，[4.3.1](#431-一般)による。

### 4.7 組織の名称及び略称

組織の名称は，その組織の正式な名称で表す。

ただし，混乱のおそれがない場合は，組織の名称を最初に用いる箇所で，正式な名称とともにその組織が用いている略称を括弧内に併記し，その後は略称だけを表記してもよい。

例 一般財団法人日本規格協会（JSA）

### 4.8 略語

略語は，混乱のおそれがない場合に限って用いる。

略語を用いる場合は，当該技術文書を通して同じ略語を用いる。

用語及び定義で略語を規定しない場合は，その略語を最初に用いる箇所で，略語の後に括弧書きで正式名称を併記する。

括弧内の正式名称の記載順序は，[8.7.4](#874-表の記載方法)による。

例1 CPU（中央処理装置）とは，一つ以上の処理機構と内部記憶装置とから成る機能単位をいう。CPUによって，…

ある用語に略語を規定した後は，当該技術文書を通して略語を用いることが望ましい。

ただし，見出し，表などの題名では，分かりやすさから，元の略さない用語を用いてもよい。

略語は，通常の単語でないことが容易に分かるように，次のいずれかによって表すことが望ましい。

a) 全てをラテン文字の大文字とし，文字の後に“.”を付けない。

例2 相対湿度（relative humidity）の略語は，RHとする（不適切な例：R.H.）。

b) 日本語の文字を用いる場合は，その分野で普及している略語に限る。

例3 サ行変格活用の略語は，サ変とする。

長い名詞（修飾語を含む。）を短く表す場合は，その名詞を最初に用いる箇所で略さずに記載し，その後に括弧書きで“（以下，○○という。）”と表記してもよい。

例4 この仕様書は，耐食用，低温用，高温用，消火用などの配管に用いるステンレス鋼鋼管（以下，管という。）について規定する。

### 4.9 表現形式

技術文書の表現形式は，読者が技術文書を正しく理解して利用できるように，できる限り簡単かつ簡潔な形式とする。

### 4.10 文

#### 4.10.1 文の長さ及び論点

一文は，短くする。一文が50字〜60字程度になった場合は，読みにくくなっていないかを見直す。

一つの文には，原則として一つの論点だけを記載する。一つの文の中に，主語と述語との関係を幾つも作らない。

接続助詞“が”及び中止法（述語の用言を連用形にして文を続ける方法）を多用せず，文を区切る。

例 “設定を変更したが，反映されず，再起動したところ，反映された。” → “設定を変更したが，反映されなかった。再起動すると，反映された。”

三つ以上の事項を並べる場合は，箇条書きにする。

手順では，一つの段階に一つの指示だけを記載する。

#### 4.10.2 語順及び係り受け

語順は，“いつ”，“どこで”，“誰が”，“何を”，“どうした”の順を基本とする。ただし，文を理解するための条件，又は強調する要素は，文頭に置いてもよい。

主語と述語との関係が分かるように書く。主語を省略する場合も，主語を読者が取り違えないようにする。

一つの文の途中で，主語を変えない。

係る語と受ける語，及び指示語と指示される語は，近くに置く。

複数の修飾節が一つの語に係る場合は，長い修飾節から順に置くか，文を分ける。

読点の位置によって意味が変わる文は，読点の位置を見直すか，書き換える。

同じ助詞（“の”，“に”，“も”，“て”など）を続けて用いない。

例 “サーバーの設定の変更の手順” → “サーバーの設定を変更する手順”

#### 4.10.3 原則及び例外

例外を伴う規則は，規則を先に述べ，例外を後に述べる。

“…の場合を除き，”のように，例外から文を始めることは避けることが望ましい。

例 “Windowsの場合を除き，インストーラーは自動で更新される。” → “インストーラーは自動で更新される。ただし，Windowsでは手動で更新する。”

例外に対する更なる例外は，避けることが望ましい。

#### 4.10.4 否定及び受動態

二重否定は，強調のために必要な場合を除いて，用いない。

例1 “管理者を除いて，削除できない。” → “管理者だけが削除の権限をもつ。”

文は，能動態で書くことを基本とする。受動態は，行為の主体が分かりにくくなる場合には用いない。

例2 “入力値は検証される。” → “APIサーバーが入力値を検証する。”

行為の主体を示す必要がない場合，及び行為の対象を目立たせる場合は，受動態を用いてもよい。

#### 4.10.5 簡潔な表現

回りくどい言い方，不要な繰り返し及び重複した表現は，用いない。

例1 “確認を実施する” → “確認する”

例2 “約10件くらい” → “約10件”

動作は，名詞を連ねて表すよりも，動詞で表すことが望ましい。

例3 “設定ファイルの作成の実施後” → “設定ファイルを作成した後”

文語の名残の言い方（“…のごとく”，“…せんとする”など）は，口語に言い換える。

## 5 数値，量，単位及び記号

小数点は，“.”を用いて表す。

1未満の数値を十進法で表す場合は，小数点の前にゼロを置く。

数値は，3桁ごとに半角スペースで区切って表記する。

ただし，2進数，16進数，暦年を表す数字及び文書番号を表す数字には，区切りを適用しない。

物理量は，アラビア数字の後にSI（国際単位系）による単位記号を付け，数値と単位記号との間に半角スペースを入れる。

平面角の度，分及び秒の単位記号は，数値の後に半角スペースを入れない。

数値の範囲を表す場合は，“10 mm〜20 mm”のように，いずれの数値にも単位記号を付ける。

百分率の許容差は，“(65±2) %”のように表記し，“65±2 %”とは表記しない。

量記号は斜体で表し，単位記号は直立体で表す。

プログラム，データ又はマークアップ言語のコードに含まれる数値及び記号は，その言語の構文による。

## 6 引用・参照

### 6.1 一般

別の文書又は当該文書の他の部分の内容は，繰り返して記載せず，文書番号，章番号などを示して引用・参照するのがよい。

他の文書の内容を転載する場合は，転載した内容の後に“（出典：[<出典の題名>](<出典のURL>)）”のように，出典をリンクで記載する。

出典元の内容を変更して転載する場合は，“（出典：[<出典の題名>](<出典のURL>)を変更）”のように記載する。

出典の中の図名，節，PDFのページ番号など，転載した内容の位置を示す場合は，リンクの後に“，”で区切って記載する。

### 6.2 当該文書内での引用・参照

当該文書内の章，節，箇条書き，注記，注，図，表及び式は，[表7](#table-7)のように，その番号を用いて引用・参照する。

<a id="table-7"></a>表7−当該文書内での引用・参照の表現形式

| 対象 | 引用の例 | 参照の例 |
| --- | --- | --- |
| 章 | 9章による。 | 9章参照。 |
| 節 | 5.1によって… | …を求める（6.1.2参照）。 |
| 箇条書き | 5章のa)によって… | 5.1.1のb)参照。 |
| 図 | …は，図3による。 | …とする（図10参照）。 |
| 表 | …は，表3による。 | 表2参照。 |
| 式 | 式(3)によって求める。 | 3.1の式(3)参照。 |

章，節，図及び表を引用・参照する場合は，番号を表記した上で，参照先のアンカーへのリンクを付ける。

ページ番号による引用・参照は，行わない。

“以下の章”，“上記の図”などの不明確な引用・参照をしてはならない。

当該文書自身は，“この規格”，“この仕様書”のように文書の種類を示す語，又は“この文書”で表記する。

### 6.3 根拠原文とのトレーサビリティ確保

根拠とのトレーサビリティを文書に記載することを明示的に求められた場合は，文及び表の記載内容を，根拠となる資料の原文と対応付けなければならない。この目的は記載内容の妥当性検証である。

見出しや図表番号などの文書形式上の記載，その他の根拠を必要としない記載及び実測記録を根拠とする記載には，資料の原文との対応付け及び根拠IDの付与を求めない。

根拠として引用した箇所には一意の根拠IDを付与し，対応する文の行末又は表の各行の末尾にコメントアウトとして記載する。

根拠情報は，参考資料とは別に設ける根拠表で管理する。この表もコメントアウトとして記載する。

根拠表は，参考文献の表の直下に配置し，“根拠ID”，“資料”及び“引用”の列を設ける。

“根拠ID”列には引用箇所に付与したIDを記載し，対応する文又は表の行末にも同じIDを記載する。

“資料”列には資料のリンク付きタイトル，該当箇所のページ，セクション等を，“引用”列にはその該当箇所の原文を記載する。

## 7 名称及び文書情報

### 7.1 名称

名称は，技術文書が取り扱う主題を明確かつ簡潔に表し，他の技術文書の主題と区別できるものとする。

名称は，全体的な分野を示す前置き要素，主題を示す主要素，主題の特定の側面を示す補完要素の順に，ハイフン“−”で分けて構成することが望ましい。

主要素は，全ての名称に含める。

### 7.2 文書情報

文書情報は，技術文書を識別し，そのステータスを示すための情報である。

文書情報は，版を管理する技術文書に設ける。

文書情報には，次に示す事項のうち，該当する事項を表に記載する。

a) 文書番号

b) 版

c) ステータス（例えば，原案，承認済み，廃止）

d) 発行者

e) 責任者

注記 発行日は，変更履歴の日付で示す。

## 8 はじめに

### 8.1 構成

はじめには，1章とし，[表8](#table-8)の節をこの順に設ける。

<a id="table-8"></a>表8−はじめにの節

| 節 | 設置 |
| --- | --- |
| 概要 | 選択 |
| 目的 | 必須 |
| 背景 | 選択 |
| 適用範囲 | 選択 |
| 上位文書 | 条件付き |
| 用語及び定義 | 条件付き |

概要及び適用範囲は，どちらか一方だけを設ける。

節は，“1.1”から設けた順に付番する。

はじめにの題名と最初の節との間には，段落を置かない（[11.3](#113-ぶら下がり段落)参照）。

### 8.2 概要

概要には，技術文書の内容の要約を記載する（[2.6](#26-概要)参照）。

### 8.3 目的

目的には，技術文書を作成する目的及び想定する読者を記載する。

### 8.4 背景

背景には，技術文書の対象が置かれている状況及び前提，制定・改訂の経緯・理由，並びに関連する技術文書との関係を記載する。

### 8.5 適用範囲

適用範囲は，技術文書が取り扱う主題及び技術文書を適用する範囲を規定する。

適用範囲は，名称の単なる繰返しとしないことが望ましい。

適用範囲は，次のような表現形式で記載する。

- “この文書は，…について規定する。”

- “この文書は，…についての指針を示す。”

- “この文書は，…に適用する。”

- “ただし，…には適用しない。”

### 8.6 上位文書

#### 8.6.1 一般

上位文書には，当該技術文書に引用されることによって，その一部又は全部が当該技術文書の要求事項を構成する文書を記載する。

例 設計書に対する要求仕様書

上位文書の適用に関する情報（部分引用の場合の章番号など）は，上位文書ではなく，本文の引用箇所に表記する。

推奨事項，許容事項又は補足事項のために引用・参照する文書は，参考文献に記載する。

上位文書は，該当する文書がある場合に設ける。

#### 8.6.2 前置き文

上位文書では，前置き文として，“次に掲げる上位文書は，この文書に引用されることによって，その一部又は全部がこの文書の要求事項を構成している。”を用いる。

#### 8.6.3 表の記載方法

上位文書は，前置き文に続けて，文書番号及び名称を列とする表で，文書ごとに1行として記載する。

文書番号の列には，文書番号及び必要な場合は西暦年又は版を記載し，文書番号がない場合は“−”を記載する。

名称の列には，文書の名称を記載し，オンラインで入手する文書は，ページの題名を表記したリンクとする。

### 8.7 用語及び定義

#### 8.7.1 一般

用語及び定義は，当該技術文書で用いる用語を理解するために必要な定義を規定する。

用語及び定義は，定義する用語がある場合に設ける。

#### 8.7.2 前置き文

用語及び定義では，前置き文として，次のいずれかの定型文を用いる。

a) 当該技術文書だけで用語を定義する場合 “この文書で用いる主な用語及び定義は，表Xによる。”

b) 別の文書で定義している用語の定義を適用する場合 “この文書で用いる主な用語及び定義は，<文書番号>による。”

c) 当該技術文書で用語を定義し，かつ，別の文書の定義も適用する場合 “この文書で用いる主な用語及び定義は，表Xによるほか，<文書番号>による。”

注記 “表X”の部分は，用語及び定義の表の番号とする。

#### 8.7.3 定義する用語

自明でない用語，一般には知られていない用語及び文脈によって異なる解釈が可能な用語は，定義を与えて概念を明確にする。

一般的な辞書にある語句は，一般的な意味とは異なる特定の意味で用いる場合にだけ定義する。

当該技術文書で用いる用語だけを定義する。

用語は，概念の階層によって列記することが望ましい。

#### 8.7.4 表の記載方法

用語及び定義は，用語及び定義を列とする表で，用語ごとに1行として記載する。

用語の列には，用語を記載し，代替用語及び推奨しない用語がある場合は，改行して“代替用語：”又は“推奨しない用語：”と表記した後に記載する。

略語を定義する場合は，用語の列に略語を記載し，その後に括弧書きで正式名称を記載する。

括弧内の正式名称は，英語の名称と日本語の名称とのうち，広く用いられている方を先に記載し，読点で区切って他方を続ける。

例 URL（uniform resource locator，ユニフォーム リソース ロケータ）

略語以外の用語には，対応英語及び読みを，用語の後に括弧書きで記載してもよい。

括弧内の正式名称，対応英語及び読みは，用語として扱わない。

定義の列には，定義を記載し，例，注釈及び出典がある場合は，定義の後に改行して，例，注釈，出典の順に記載する（出典の表記は[6.1](#61-一般)参照）。

#### 8.7.5 定義

定義は，できる限り当該用語に置き換えることが可能な句の形式で記載する。句又は文のいずれで記載する場合も，末尾に句点を付ける。

定義の文中に，定義する当該用語を含めてはならない。

一つの用語で複数の概念を定義する必要がある場合は，概念ごとに行を分け，それぞれの定義文の前に山括弧“＜ ＞”を付けて適用領域を示す。

#### 8.7.6 注釈

注釈には，用語の使用に関する事項を記載する。

## 9 参考文献

参考文献には，文書の作成時に参照し，記述の根拠として採用した資料（[2.11](#211-根拠)参照），及び読者が文書の理解を深めるために参照する資料を記載する。

参考文献は，記載する資料がある場合に設ける。

参考文献は，章番号を付けず，見出しを“参考文献”とし，本文の最後の章の後に置く。

参考文献の表には，本書の章，参考文献及び概要の三つの列を設ける（[参考文献](#参考文献)参照）。

本書の章の列には，その資料を用いた箇所を章の単位で記載し，節は挙げない。

参考文献の列には，資料の題名を表記したリンクを記載する。

リンク先は，参照した記述が書かれているページとする。

概要の列には，その資料の概要を記載する（[2.6](#26-概要)参照）。

参考文献は，資料1件につき1行とし，同じ章で複数の資料を用いる場合も，資料ごとに行を分ける。

1件の資料が複数の章にかかる場合は，その行の本書の章の列に，見出しを改行で区切って並べる。

必要な情報が一つのページに収まっている場合は，節又は項ごとのURLに分けず，そのページを1件として記載する。

同じ資料に日本語版のページがある場合は，日本語版のURLを記載する。

一つの文書を要求事項として引用し，参考としても参照する場合は，その文書を上位文書に記載し，参考文献には記載しない。

## 10 変更履歴

変更履歴には，技術文書の版ごとの変更を記載する。

変更履歴は，章番号を付けず，見出しを“変更履歴”とし，参考文献の後に置く。

変更履歴は，版，日付及び変更内容を列とする表で記載し，新しい版を下の行に追加する。

要求事項に影響する変更は，変更した章番号及び変更の要点を記載する。

## 11 章及び節

### 11.1 題名

各章には，題名を付ける。

第1階層の節には，題名を付けることが望ましい。

同じ章又は節の中では，その下の同じ階層の節の題名の有無を統一する。

### 11.2 付番及び区分け

章番号は，“はじめに”を“1”とし，続き番号とする。

節は，第5階層（例えば，“6.4.2.2.2.1”）まで設けてもよい。

節の階層は，できるだけ少なくすることが望ましい。

節は短くし，各節の内容を一つの見出しで要約可能な範囲にとどめる。

一つだけの節は設けない。

例 後続の節“10.2”がない場合，10章の中に“10.1”という節は設けない。

### 11.3 ぶら下がり段落

節をもつ章又は節の題名と最初の節との間に置いた段落（ぶら下がり段落）は，避けなければならない。

ぶら下がり段落の内容は，“5.1 一般”のような節とするか，適切な箇所に移動する。

注記 用語及び定義の前置き文は，ぶら下がり段落ではない。

## 12 箇条書き

箇条書きは，段落の中の情報を整理するために列記する項目である。

箇条書きは，引用・参照する場合には，“a)”，“b)”のように，ラテン文字の小文字に片括弧を付けて付番する。

付番した箇条書きを更に細分する場合は，“1)”，“2)”のように，アラビア数字に片括弧を付けて付番する。

同じ章又は節の中では，同じ付番の符号を繰り返して用いない。

付番した箇条書きは，それぞれ独立した段落として記載する。

付番しない箇条書きは，項目の前に“−”又は“・”を付けて記載する。

読み上げたときに区別が付かない行頭記号（“あ”と“ア”と，“1”と“一”となど）を，並べて用いない。

箇条書きには，通常，題名を付けない。

## 13 注記，例及び注

### 13.1 注記

注記は，技術文書の理解又は利用を支援するための追加情報を提供するために用いる。

技術文書は，注記がなくても利用できるものでなければならない。

注記は，一つの章（節があれば節）ごとに“注記1”，“注記2”のように付番し，一つだけの場合は付番せずに“注記”と表記する。

### 13.2 例

例は，技術文書の規定を例示によって説明するために用いる。

技術文書は，例がなくても利用できるものでなければならない。

例は，一つの章（節があれば節）ごとに“例1”，“例2”のように付番し，一つだけの場合は付番せずに“例”と表記する。

### 13.3 注

注は，本文中の特定の語句又は文に対する追加情報を提供するために用いる。

技術文書は，注がなくても利用できるものでなければならない。

注は，該当する段落の後に“注1)”のように記載し，本文の該当する語句の後に上付きの注符号“1)”を付ける。

注には，技術文書全体を通じた一連番号を付ける。

## 14 式

式を引用・参照する必要がある場合は，“(1)”のように括弧を付けた一連番号を式の右に付ける。

式の番号には，“(2a)”，“(2.1)”のような分割する番号を用いない。

式に用いる量記号の意味は，式の後に“ここで，”に続けて記載する。

量の名称及び複数文字の略語を量記号として用いてはならない。

## 15 図

図には，本文を通して“図1”，“図2”のように，“1”から始まる連続した番号を付ける。

図が一つの場合にも，“図1”と表記する。

図の番号に章番号を組み合わせない。

図の番号及び題名は，図の後に“図1−装置の構成”のように，ハイフン“−”で分けて表記する。

図には，題名を付けることが望ましい。

図は，当該技術文書の他の部分で引用又は参照しなければならない。

細分図は，1段階だけとし，“a)”，“b)”のように付番する。

図の注記は，図の番号及び題名の前に記載する。

図の注は，図ごとに“注a)”，“注b)”のように付ける。

グラフには，軸の名称及び必要に応じて凡例を示す。

色の違いだけで情報を区別しない。白黒で印刷した場合にも区別が可能になるようにし，多くの色を使うことは避ける。

図中の要素を説明する場合は，図に続けて“要素”，“位置”及び“説明”の列をもつ表を設ける。“要素”には図中の表記をそのまま記載し，図中の略語の正式名称が確認できる場合は括弧内に補う。“位置”には図中での位置を，“説明”には要素の役割又は関係を記載する。

## 16 表

表には，本文を通して“表1”，“表2”のように，“1”から始まる連続した番号を付ける。

表が一つの場合にも，“表1”と表記する。

表の番号に章番号を組み合わせない。

表の番号及び題名は，表の前に“表1−機械的性質”のように，ハイフン“−”で分けて表記する。

表には，題名を付けることが望ましい。

表は，当該技術文書の他の部分で引用又は参照しなければならない。

表の中に更に表を作成してはならず，表を“表1 a)”のような細分表に分割してはならない。

各欄の数値の単位が全て同じ場合は，表の前に“単位 mm”のように表記する。

表の一部に空欄がある場合は，“−”を入れる。

表の注記及び注は，表の最下部の枠内に，注記，注の順で記載する。

表の注は，表ごとに“注a)”，“注b)”のように付ける。

一つのセルに複数の名称又は項目を列挙する場合は，Markdownの`<br>`で項目ごとに改行し，列挙の末尾に句点を付けない。説明文には，通常の文章と同じように句点を付ける。
