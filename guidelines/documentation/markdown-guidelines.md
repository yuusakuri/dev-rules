# Markdown記述ガイドライン

本書は、Markdownで文書を書くときの改行、空行、表、リンクの記述方法を定めます。

## 段落と改行

本文の中で文を区切るときは、単一の改行ではなく、空行を挟んだ改行2回で区切ります。
Markdownは連続した行を1つの段落としてまとめるため、単一の改行では文が前の文につながって表示され、意図した位置で段落が分かれません。

記載例を次に示します。

```markdown
1つ目の段落です。

2つ目の段落です。
```

## ブロックの前後の空行

表、コードブロック、箇条書きリストの前後には、1行の空行を挟みます。
空行がないと、直前や直後の段落と一続きの本文として解釈され、ブロックが表や一覧として描画されません。

記載例を次に示します。

````markdown
次の項目を確認します。

- 1つ目の項目
- 2つ目の項目

確認できたら、次のコマンドを実行します。

```bash
npm test
```

実行結果を記録します。
````

## 表の記述

セルの中で改行するときは、単一の改行ではなく `<br>` タグを使います。
表は1行で1レコードを表す構造のため、セルの途中で改行すると行の区切りが崩れ、表として認識されなくなります。

セルの中で項目を並べるときも、`-` による箇条書きは使わず `<br>` で区切ります。
箇条書きはブロック要素であり、セルの中には置けないためです。

セルの中に `|` を書くときは、`\|` とエスケープします。
リンクのタイトルに含まれる `|` も同じくエスケープします。
エスケープしないと列の区切りとして解釈され、列がずれます。

記載例を次に示します。

```markdown
| 項目 | 内容 |
| --- | --- |
| 対応環境 | Windows<br>macOS<br>Linux |
| 参照 | [Tables \| Google developer documentation style guide](https://developers.google.com/style/tables) |
```

## リンクの記述

リンクは `[<ページタイトル>](<URL>)` の形式で記載します。

参照先に日本語版のページがある場合は、日本語版のURLを指定します。
読者が翻訳を探さずに内容を読めるようにするためです。

ページタイトルは、参照先のページの `<title>` タグの内容をそのまま使います。
要約したり言い換えたりすると、読者が参照先で同じページを見つけられなくなります。
