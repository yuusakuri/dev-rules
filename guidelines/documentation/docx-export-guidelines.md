# MarkdownからDOCXへの変換ガイドライン

## 1 適用範囲

このガイドラインは、Markdownを正本とし、編集可能なDOCXを配布用成果物として生成する場合に適用する。Googleドキュメントへ変換する場合も、DOCXの確認事項を適用する。

## 2 正本と生成方法

MarkdownとDOCXで別々に本文を編集しない。本文の修正後にDOCXを再生成し、両方を同じ変更として管理する。

変換に使うプログラム、依存パッケージの版、実行コマンドをリポジトリに記録する。生成したDOCXのファイル名は、対応するMarkdownと同じ基底名にする。

## 3 文書要素

見出しは見出しスタイル、表は編集可能な表、画像は埋め込み画像として出力する。箇条書き、強調及び外部リンクも、それぞれDOCXの対応する要素に変換する。画像・表・脚注などの参照番号と本文の対応を保つ。

Markdownの内部リンクは、変換前に全リンクの参照先が存在することを検査する。DOCXで内部リンクを使う場合は、ブックマークと内部ハイパーリンクに変換する。Googleドキュメントへ取り込むDOCXでブックマークアイコンを避ける場合は、図表及び本文中の節参照を通常の文字として出力し、目次には見出しスタイルから生成するTOCフィールドを用いる。Markdownのリンクは保持する。

書式の指定がない場合、本文と見出しにはArial、コードにはRoboto Monoを用いる。各要素の文字サイズは次のとおりとする。見出しには文字サイズだけでなく見出しスタイルを設定する。

| 要素 | 文字サイズ |
| --- | ---: |
| タイトル | 26 pt |
| サブタイトル | 15 pt |
| 見出し1 | 20 pt |
| 見出し2 | 16 pt |
| 見出し3 | 14 pt |
| 通常のテキスト | 11 pt |
| インラインコード | 11 pt |
| コードブロック | 9 pt |

## 4 確認

生成後に、MarkdownとDOCXの見出し、表及び画像の件数と内容を照合する。内部リンクを出力する方針の場合は，リンクの件数と移動先も確認する。本文参照を通常の文字に変換する方針の場合は，意図しない内部リンクやブックマークが残っていないことを確認する。ページ表示で表の分断、画像の欠落、文字の重なり及び欠字も確認する。

Googleドキュメントへ取り込む場合はGoogleドキュメント形式へ変換し、見出しスタイル、表、画像及びフォントを確認する。目次フィールドの取り込み結果は変換後の文書画面で確認する。目次が見出しへ移動できない場合は、Googleドキュメントの見出しスタイルに基づく目次を挿入する。ブックマークアイコンを避ける方針の場合は、見出し横にアイコンが出ないことも確認する。変換後の文書を更新する場合は、Markdownを修正してDOCXとGoogleドキュメントを再生成するか、三者の内容を同期させる。
