## 1. 概要

本書は、テストで何を検証するかを定義する。本書は、[ソフトウェア設計ガイドライン](software-design-guidelines.md)を前提とする。

テストの種別ごとの配分と検証対象は、[アプリケーション設計ガイドラインの「テスト」](application-design-guidelines.md#6-テスト)に従う。

## 2. 検証の方針

### 実装の手順ではなく期待する振る舞いを検証する

テストでは、対象がどの関数をどの順で呼んだかではなく、対象に期待する振る舞いが実現されているかを検証する。実装の手順を書き写したテストは、本番コードを変更するだけで失敗する一方で、変更前後のどちらについても正しさを確認できないため、欠陥を見つけないまま保守の手間だけを増やす。

### 観測できる結果があるときは状態を検証する

戻り値、対象や協力先の状態、永続化された内容など、処理の後に観測できる結果があるときは、その結果を検証する。呼び出しの検証は対象が正しく動いたことまでは示さないのに対し、状態の検証は結果そのものを確認するため、同じ振る舞いを保ったまま内部構造を変更してもテストを維持できる。

### 状態で確認できない場合にインタラクションを検証する

状態だけでは正しさを確認できない場合は、呼び出し先、引数、回数、順序など、必要なやり取りを検証する。該当するのは次の場合である。

| 場合 | 例 |
| --- | --- |
| 実物やFakeを使えず、結果を状態として観測できない | メール送信、イベント発行、決済要求など、外部への作用が期待する振る舞いである処理 |
| 呼び出しの回数や順序の違いが望まない振る舞いを生む | 重複した送信、余分なディスク読み取り、順序の誤りによるデッドロック |
| 出力の内容だけでなく、その求め方が要件に含まれる | 性能要件を満たすために特定のアルゴリズムを使う処理 |
| 描画の詳細を分離したUIで、表示側への指示が対象の責務である | MVCやMVPのControllerやPresenter |

### 外部への作用は作用の内容まで検証する

外部への作用を検証するときは、呼び出しの有無だけでなく、宛先、内容、回数など、要件が定める作用の中身まで確認する。確認したいのは特定のメソッドが呼ばれたことではなく、要件どおりの作用が発生したことである。

## 3. 内部実装の呼び出し

### 観測できる結果があるときは内部の呼び出しを検証しない

利用者から観測できる結果で正しさを確認できる場合は、補助関数、Factory、内部で組み立てた協力先などの呼び出しを検証しない。利用者はこれらの存在を意識しないため、呼び出しを検証すると、振る舞いを変えないリファクタリングでもテストが失敗する。

### private関数は公開された振る舞いを通して検証する

private関数やprivateメソッドの処理は、それを使う公開された操作の結果として検証する。公開された操作から検証できない処理が残る場合は、テスト方法ではなく、責務の分け方を見直す。

## 4. Test Doubleの選び方

### 実物を優先する

依存先には実物の実装を優先して使い、実物を使えない場合にTest Doubleへ置き換える。実物を使うほど、テストは本番の動作に近づき、対象が正しく動いていることを確かめられる。

実物を使えない場合は、実物と同じ振る舞いを持つFakeを次の候補にする。Stubは、対象を目的の状態にするために特定の値を返させる場合に限って使う。

### 目的に応じて種類を選ぶ

Test Doubleは、テストで果たす役割ごとに次の種類がある。

| 種類 | 役割 |
| --- | --- |
| Dummy | 引数を埋めるためだけに渡し、処理では使用しない。 |
| Fake | 実物と同じ働きをする軽量な実装を持つが、本番では使えない近道を含む。 |
| Stub | テストで決めた値を返し、対象を目的の状態にする。 |
| Spy | Stubとして応答しながら、呼び出された内容を記録する。 |
| Mock | 期待する呼び出しをあらかじめ設定し、そのとおりに呼ばれたかを判定する。 |

### 外部サービスの置き換えはContract Testで裏付ける

外部サービスをTest Doubleへ置き換える場合は、Contract Testを設け、Test Doubleの応答が実際のサービスの契約と一致していることを定期的に確認する。外部サービスの変更にTest Doubleが追随できないと、テストは通るのに本番では動かない状態になる。

## 5. 検証対象ごとの検証内容

| 検証対象 | 主に検証する内容 |
| --- | --- |
| 計算処理 | 戻り値 |
| 変換処理 | 出力結果 |
| ドメインロジック | 公開された結果や状態 |
| エンティティ | 公開された状態 |
| DBへの保存 | 永続化された結果 |
| API | レスポンスと外部から観測できる作用 |
| ファイル出力 | 出力された内容 |
| メール送信 | 送信要求の宛先、内容、回数 |
| イベント、メッセージ送信 | 発行内容と、要件が定める回数や順序 |
| 決済などの外部サービス | 外部へ送る要求の内容 |
| private関数、privateメソッド | 公開された振る舞い |
