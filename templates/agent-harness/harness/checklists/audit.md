# 監査のチェックリスト

- 全ての対象ホストについて、CPUの型番と命令セット、コア数、メモリ、ディスク、ホスト間の通信遅延を確認した。
- 計測を、一部のホストではなく全ての対象ホストから集めている。
- 処理速度を制限する資源（CPU、I/O、ネットワーク、ロック、外部サービス）を特定し、直近の変更がその資源を対象にしている。
- 余っている資源又はホストを、処理の移し先として検討した。
- 基準を複数回測り、揺れを把握したうえで残すか戻すかを決めている。
- 変更を戻したときに、コードに加えてデータベース、設定及び常駐プロセスも戻している。
- 評価の出力のエラーと警告を読み、失敗の原因を記録している。
- アプリケーション以外の構成要素（ミドルウェア、OSの設定、問題に付属する補助サービス）も変更対象として検討した。
- データの持ち方の変更、キャッシュ、計算の省略、処理の配置の変更など、構造を変える案を検討した。
- 計測そのものによる負荷が、評価の結果をゆがめていない。
