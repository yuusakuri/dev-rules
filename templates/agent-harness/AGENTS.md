# エージェントへの常設の指示

この指示は、このファイルがハーネスを導入したリポジトリのルートにあるときに適用する。

このリポジトリでは、エージェントが終了時刻まで人の介入なしに、CONDITIONS.md の目標に向けて改善を繰り返す。

## 自律で動くための前提

人は作業中に応答しない。質問や確認の依頼を出さず、判断に必要な材料を計測と記録からそろえて、自分で決める。

終了時刻、段階、最高スコア、基準は、`python3 harness/harness.py status` で確認する。

作業の途中で処理が終了しても、ハーネスが同じセッションを再開する。再開後は `status` と `runs/current/journal.md` から状態を把握して続ける。

## 最初にすること

1. CONDITIONS.md を読み、目標、評価方法、規約、禁止事項、最終状態の要件を確認する。
2. `improvement-playbook` スキルの初期調査を行う。
3. 何も変更していない状態で `python3 harness/harness.py evaluate --label baseline --repeat 3` を実行し、基準のスコアと揺れを測る。

## 改善の手順

1回の改善は、次の順で行う。

1. 直近の評価で集めた計測（`runs/current/logs/eval-<番号>-collect/`）から、資源を最も使っている箇所を特定する。
2. 仮説を `runs/current/hypotheses/<番号>-<名前>.md` に書く。仮説には、変更する仕組み、計測による根拠、期待する効果を書く。
3. 1件の仮説を1件のコミットとして実装する。
4. `python3 harness/harness.py deploy` で環境へ反映する。
5. `python3 harness/harness.py evaluate --label candidate` で評価する。
6. 判定の目安に従って、変更を残すか戻すかを決める。
   - keep: 変更を残し、`evaluate --label baseline --repeat 3` で新しい基準を測る。
   - revert: `git revert` でコミットを戻し、`python3 harness/harness.py rollback <戻す先のコミット>` でデータベースや設定を含む環境を戻す。
   - remeasure: 同じコミットを再度評価する。
7. `python3 harness/harness.py journal` で、目的、変更、予想、結果、理由、判断を記録する。

## 判断の規則

- 評価の出力は、スコアより先にエラーと警告を読む。評価に失敗した変更は残さない。
- 推測と、エージェントが出した結論は、計測で裏付けるまで仮説として扱う。
- 基準の揺れより小さい差は、改善として扱わない。
- 律速している資源と異なる資源を改善する変更は、後回しにする。
- 使われていない資源があれば、処理の移し先として検討する。
- 実装に時間がかかるという見積もりだけを理由に、大きな構造の変更を捨てない。小さな試作で効果を確かめてから決める。

## 停滞したとき

最高スコアが一定時間更新されない場合は、ハーネスから通知が届く。通知を受けたら、次を行う。

1. `auditor` 補助エージェントを起動し、記録された判断をチェックリストと照合させる。
2. `fresh-proposer` 補助エージェントを起動し、これまでの経緯を渡さずに、構造を変える案を出させる。
3. 両方の報告から、根拠と期待効果の大きい仮説を選んで改善の手順へ戻る。

## 操作の規則

- 環境の反映、復元、再起動の確認は、`harness/harness.py` のサブコマンドで行う。
- 長い出力はファイルへ保存し、必要な箇所だけを読む。

## 最終段階

最終段階に入ると、ハーネスから通知が届く。最終段階では新しい改善に着手せず、次を行う。

1. `status` に表示される基準のコミット（keep と判定して基準を測り直した最新のコミット）へ戻し、`deploy` で反映する。revert と判定したコミットは、個々の評価のスコアが高くても使わない。
2. 採点に不要な計測を止め、計測による負荷を取り除く。
3. 状態を定期的に変更するジョブのうち、最終状態の要件に反するものを止める。
4. `python3 harness/harness.py verify-restart` で、再起動後に状態が復元されることを確かめる。
5. `python3 harness/harness.py evaluate --label final --repeat 3` で、最終状態のスコアを確かめる。採点に最後の評価が使われる場合は、同じコミットの評価の分布から期待値を求め、期待値を上回るまで評価を繰り返す。
6. CONDITIONS.md の最終状態の要件を満たしていることを確かめる。
7. `python3 harness/harness.py finish --report "<最終状態の要約>"` で終了を記録する。
