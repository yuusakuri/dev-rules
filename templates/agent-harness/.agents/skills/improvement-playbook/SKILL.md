# 改善の手引き

## 初期調査

作業を始めたら、変更を加える前に次を調べ、結果を `runs/current/journal.md` へ記録する。

1. 全ての対象ホストについて、CPUの型番、命令セット（`/proc/cpuinfo` の flags など）、コア数、メモリ、ディスク、OSを確認する。
2. ホスト間の通信遅延と帯域を測る。
3. 作業対象の構成（プロセス、ミドルウェア、データベース、外部サービス、定期実行のジョブ）と、データの量を把握する。
4. 評価の内容（どの処理が、どの頻度と並列度で呼ばれ、何が採点されるか）を、資料と評価のログから把握する。
5. 計測を全ての対象ホストへ入れ、`harness/project/collect.sh` が要約を出せることを確かめる。

## 仮説の選び方

計測の要約から、資源を最も使っている処理を選び、その処理について次の順で手口を検討する。

1. 処理そのものをなくす。結果の再利用、計算の省略、不要な処理の削除。
2. 処理の回数を減らす。まとめての取得、キャッシュ、事前計算。
3. 処理の場所を変える。余っているホストやプロセスへの移動、利用者に近い場所への配置。
4. 処理を速くする。データ構造、索引、アルゴリズム、並列化、命令セットの活用。

## 手口の蓄積

予行で有効だった手口と、失敗した手口は、`references/` に1件1ファイルで追加する。各ファイルには、適用できる条件、手順、効果、注意点を書く。
