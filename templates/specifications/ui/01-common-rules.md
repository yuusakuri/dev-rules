## 1. 画面の状態

各画面は次の状態を検討する。個別画面の仕様では、対象外の状態にも「対象外」と理由を記載し、空欄にしない。

| 状態 | 説明 | 共通の表示 |
| --- | --- | --- |
| Initial | 画面を開いた直後の状態 | <表示内容> |
| Loading | 初回データを取得中の状態 | <表示内容> |
| Loaded | データ取得または操作が成功した状態 | <表示内容> |
| Empty | 正常に取得できたが表示対象が0件の状態 | <表示内容と、次に実行できる操作> |
| Refreshing | 現在の表示を維持したまま再取得している状態 | <表示内容> |
| Submitting | 登録、更新、削除などを処理中の状態 | <表示内容> |
| Error | 通信またはサーバー処理が失敗した状態 | <表示内容と再試行手段> |
| Forbidden | 閲覧または操作の権限を持たない状態 | <表示内容と遷移先> |
| SessionExpired | 認証情報が失効した状態 | <表示内容と遷移先> |
| Conflict | 他の更新と競合した状態 | <表示内容と、次に実行できる操作> |

## 2. 通信中の表示

| 対象 | 規則 |
| --- | --- |
| 初回取得 | コンテンツ領域へ<スケルトンまたはローディング表示>を表示する。 |
| 再取得 | 現在の表示を維持し、<更新中であることを示す表現>を表示する。 |
| 登録、更新、削除 | 実行ボタンを無効化し、<処理中であることを示す表現>を表示する。 |
| 二重送信 | 同一処理の完了前に再送信しない。 |
| 長時間処理 | 進行状況を取得できる場合は、<進捗の表示方法>を表示する。 |

## 3. エラー表示

| 種別 | 表示位置 | 規則 |
| --- | --- | --- |
| 入力項目単位のエラー | 対象入力欄の直下 | エラー内容と修正方法をテキストで表示する。 |
| フォーム全体のエラー | フォーム上部 | エラーサマリーを表示し、対象入力欄へ移動できるリンクを付ける。 |
| 通信エラー | <コンテンツ領域または通知領域> | 原因に応じたメッセージと再試行手段を表示する。 |
| 操作失敗 | 通知領域 | 失敗した操作と、次に実行できる操作を表示する。 |
| 権限不足 | <画面全体または対象操作箇所> | 閲覧不可または操作不可であることを表示する。 |

色だけ、またはアイコンだけでエラーを表現せず、必ずテキストを表示する。

複数の検証エラーが同時に発生する場合は、画面上部から下部の順に並べる。フォーム上部のエラーサマリーも同じ順序で表示する。

| 項目 | 規則 |
| --- | --- |

| バリデーション契機 | <入力中、フォーカスアウト時、送信時のどの時点で検証するか>とする。 |

| 未保存変更 | <画面離脱時に確認する条件>とする。 |

## 6. 削除と不可逆操作

| --- | --- |

## 8. デザイントークン

寸法、色、文字は数値ではなくトークン名で記述する。トークン名で記述することで、デザインシステムの変更が仕様書の記述を変えずに全体へ波及する。

| 種別 | トークン名 |
| --- | --- |
| テキスト色 | `color.foreground` |
| 背景色 | `color.surface` |
| エラー色 | `color.danger` |
| 余白 | `space.4` |
| 角丸 | `radius.md` |
| 文字 | `font.size.md` |
| 影 | `shadow.md` |
| アイコンサイズ | `icon.size.md` |

トークンが定義されていない値は、生の数値を記述する。
