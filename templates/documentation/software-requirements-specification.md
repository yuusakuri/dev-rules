## 1. はじめに

この文書が何のために存在し、誰が、どのような場面で読むのかを2文から4文で記載する。実現手段には触れない。

## 3. 要求

この章には、実装と検証ができる粒度で、外部から観測できる要求を記載する。実現手段は記載せず、設計文書へ委ねる。

要求は1件につき次の形式で記載する。

| 項目 | 内容 |
| --- | --- |
| 識別子 | <REQ-FUNC-001> |
| 名称 | <要求を一言で表す名称> |
| 記述 | <システムが満たす挙動を1文で記載する。「〜する」と言い切り、「適宜」のような解釈に幅のある語は使わない。> |
| 根拠 | <この要求が必要な理由を1文から3文で記載する。> |
| 受け入れ基準 | <満たしていれば合格と判断できる条件を、数値と単位を添えて記載する。> |
| 検証方法 | <テスト、分析、検査、実演のいずれかを記載する。> |
| 補足 | <関連する資料へのリンクや未確定の事項を記載する。> |

識別子は `REQ-<領域>-<連番>` の形式にする。領域には、その要求を記載する節に対応する次の記号を使う。

| 領域 | 対応する節 |
| --- | --- |
| FUNC | 3.2 機能 |
| INT | 3.1 外部インターフェース |
| PERF | 3.3.1 性能 |
| SEC | 3.3.2 セキュリティ |
| REL | 3.3.3 信頼性 |
| AVAIL | 3.3.4 可用性 |
| OBS | 3.3.5 可観測性 |
| COMP | 3.4 法令と規格への適合 |
| INST | 3.5.1 インストール |
| BUILD | 3.5.2 ビルドと配信 |
| DIST | 3.5.3 分散配置 |
| MAINT | 3.5.4 保守性 |
| REUSE | 3.5.5 再利用性 |
| PORT | 3.5.6 移植性 |
| COST | 3.5.7 費用 |
| DEAD | 3.5.8 期限 |
| POC | 3.5.9 概念実証 |
| CM | 3.5.10 変更管理 |
| ML | 3.6 AIと機械学習 |

一度付けた識別子は変更せず、ほかの要求へ再利用しない。要求の内容を変えたときは、変更履歴へ記録する。

### 3.1 外部インターフェース

システムが受け取る入力と、外部へ返す出力を記載する。形式、プロトコル、時間の制約を示し、スキーマがある場合はその位置を参照する。

#### 3.1.1 ユーザーインターフェース

画面の要素、操作の流れ、従うデザイン指針を記載する。エラー時と空の状態の挙動、キーボード操作、多言語対応も含める。視覚デザインはUI仕様書で管理し、ここからは参照するにとどめる。

<ユーザーインターフェースの要求>

#### 3.1.2 ハードウェアインターフェース

対応する機器の種類、やり取りする信号、通信プロトコル、応答時間や処理量の期待値を記載する。

<ハードウェアインターフェースの要求>

#### 3.1.3 ソフトウェアインターフェース

連携する外部システムの名称とバージョン、提供または利用するAPI、やり取りするデータ、通信方式、上限値とタイムアウト時の挙動を記載する。

<ソフトウェアインターフェースの要求>

### 3.2 機能

外部から観測できる挙動を、機能またはユースケース単位で記載する。入力、それに対する処理、出力を対応付けて示す。

<機能の要求>

### 3.3 サービス品質

数値で測れる品質の要求を記載する。

#### 3.3.1 性能

応答時間、処理件数、同時利用者数のような時間に関する目標と、メモリー、ストレージ、通信帯域のような資源に関する目標を記載する。

<性能の要求>

#### 3.3.2 セキュリティ

通信経路と保存データの保護、認証と認可、暗号化、監査ログを記載する。安全性、機密性、プライバシー、完全性の観点を含める。

<セキュリティの要求>

#### 3.3.3 信頼性

仕様どおりに動作し続ける能力を記載する。平均故障間隔、冗長構成、切り替え、再試行の方針が対象になる。

<信頼性の要求>

#### 3.3.4 可用性

サービスを提供できる状態にある割合を記載する。目標とする稼働率、計画停止の時間帯、復旧目標時間が対象になる。

<可用性の要求>

#### 3.3.5 可観測性

ログ、メトリクス、トレース、通知、ダッシュボードについて、取得する内容と保持期間を記載する。

<可観測性の要求>

### 3.4 法令と規格への適合

従う法令、規格、契約、社内規程を記載する。根拠となる条文や条項を示し、適合を判断できる条件を添える。

<適合に関する要求>

### 3.5 設計と実装

設計、配布、保守に対する制約と指定を記載する。

#### 3.5.1 インストール

対応する実行環境、事前に必要なもの、設定手順を記載する。

<インストールに関する要求>

#### 3.5.2 ビルドと配信

依存関係の管理、自動化、成果物の完全性と追跡可能性について記載する。

<ビルドと配信に関する要求>

#### 3.5.3 分散配置

配置の構成、データの複製と配置先、機器の分散について記載する。

<分散配置に関する要求>

#### 3.5.4 保守性

変更、修正、機能追加をしやすくするための条件を、測れる形で記載する。分割の方針、従う規約、文書、可観測性が対象になる。

<保守性に関する要求>

#### 3.5.5 再利用性

ほかの製品や機能から再利用することを前提とする部品と、その条件を記載する。

<再利用性に関する要求>

#### 3.5.6 移植性

対応するOS、実行環境、クラウド事業者を記載する。

<移植性に関する要求>

#### 3.5.7 費用

設計と実装の選択に影響する費用の上限を記載する。クラウドの利用料、取引1件あたりの費用、ライセンス料が対象になる。

<費用に関する要求>

#### 3.5.8 期限

節目、提供日、提供の判断に使う条件を記載する。

<期限に関する要求>

#### 3.5.9 概念実証

概念実証を行う場合は、その目的、範囲、期間、成功と判断する条件を記載する。

<概念実証に関する要求>

#### 3.5.10 変更管理

変更をどのように取り込み、誰へ、どのように伝えるかを記載する。変更の分類、必要な成果物、承認の流れが対象になる。

<変更管理に関する要求>

### 3.6 AIと機械学習

機械学習を用いる場合に固有の要求を記載する。用いない場合は「対象外」と理由を記載する。

#### 3.6.1 モデルの仕様

モデルの目的、入力と出力、性能の目標値、検証に使うデータ、版の管理方法を記載する。

<モデルの仕様に関する要求>

#### 3.6.2 データの管理

学習と評価に使うデータの入手元、ラベル付け、匿名化、保持期間を記載する。

<データの管理に関する要求>

#### 3.6.3 ガードレール

システムを許可された範囲で動作させるための制御を記載する。入力の検証、出力の絞り込み、実行できる操作の制限が対象になる。

<ガードレールに関する要求>

#### 3.6.4 倫理

公平性、透明性、説明責任について、測る指標と守らせる手段を記載する。

<倫理に関する要求>

#### 3.6.5 人による関与

人が確認する時点、判断を引き継ぐ条件、意見を取り込む仕組みを記載する。

<人による関与に関する要求>

#### 3.6.6 モデルのライフサイクルと運用

配置、監視、再学習、利用終了の手順と条件を記載する。

<モデルのライフサイクルと運用に関する要求>
