## 2 テスト設計の流れ

### 2.1 テスト設計の流れの要点

テスト設計では、次のステップを順に行うこととする。

処理の流れを[図1](#figure-1)に示す。

```mermaid
flowchart TD
    FS["機能仕様書"] --> TDS
    TP["テスト計画書"] --> TDS

    subgraph TDS["テスト設計仕様書"]
        direction TB
        FL["機能一覧"]
        X["×"]
        VL["観点一覧"]
        FL --- X
        X --- VL
    end

    TDS --> TM["テストマップ"]
    TM --> FC["機能動作確認一覧"]
    FC --> DETAIL["テスト明細"]
    TDS --> DETAIL
    DETAIL --> CASE["テストケース"]
```

<a id="figure-1"></a>図1−処理の流れ

### 2.2 テスト対象項目を細分化する

テスト計画書に記載のテスト対象項目をテスト設計が容易な単位に細分化する。

作成資料：機能一覧　等

### 2.3 テスト観点を細分化する

テスト計画書に記載のテスト観点をテスト設計が容易な単位に細分化する。

作成資料：観点一覧　等

### 2.4 (1)、(2)で抽出した内容をマトリクス化する

テスト対象項目とテスト観点とでマトリクスを作成し、テスト実施可否及び重要度を決定する。

作成資料：テストマップ　等

### 2.5 (1)で抽出した機能に必要な検証内容を洗い出す

テスト対象項目に対して、各機能の目的を考慮し、その達成確認のために必要な確認内容を洗い出す。

作成資料：機能動作確認一覧　等

### 2.6 テスト明細を作成する

テスト実施対象機能ごとに、テスト観点に合わせた入力内容を抽出及び策定する。

作成資料：テスト明細　等

### 2.7 テストケースを作成する

テスト明細を基に、具体的なテスト手順書（テストケース）を作成する。

作成資料：テストケース
